## 목적과 가설
1. [사실] 첫 실물의 팔 진동 원인 진단 → 추론 방식·필터로 줄이기.
2. [가설] 공식 lerobot-rollout 과 우리 래퍼의 차이가 실패 원인인가 → 아님.
3. [사실] 필터가 성공률을 바꾸는가 (A/B 40판).
4. [사실] K3 대 K1/K4 차이가 로봇 기하(정면) 탓인지 카메라 탓인지 (공간 평가).

## 추론 설정
- 첫 실물: sync, denoise 10, 필터 없음, max_relative_target 8°.
- 이후 표준: **RTC h20, prefix EXP, guidance 10, queue 30, denoise 5**, max_relative_target 8°; 필터 = 팔 5관절 EMA α 0.5 + 속도 제한 (그리퍼 제외).
- 큐브 회전 통제 없음 (사후 측정), 시작 자세 pan −4…−1.4°.

## 오프라인 분석 (학습 데이터·기록 재생)
- [사실] 체크포인트 5k→20k 파지 자세 오차 6.47 → 5.43°, 잡음 0.92–1.09° 평탄 (학습 데이터, held-out 아님).
- [사실] P0 재생: RTC h20 EXP s5 + EMA 필터 → 경계 점프 0, 잡음 0.45°.
- [사실] 필터 끈 래퍼 = 공식 lerobot-rollout 출력 (차 0.0).
- [사실] 파지 직전 손목 기준 큐브–집게 각도: 정책 성공 2.0° vs 실패 15.3° (p=1.1e-5); 위치·정렬 정상 사람 87% vs 정책 32%.

## 실패 사례
[관찰] 큐브 밀림, 얕은 파지, 미끄러짐; 메모 "계속 좌측으로 갈려고… 학습한 데이터의 절대위치를 기억하나?", "wrist가 돌아가면 잡기 어려워하는거 같음".

## 분석 결과
- [가설] 큰 진동 = sync chunk 경계 + 모델 잡음; RTC 로 대부분 해소, 필터는 성공률 무관.
- [가설] 실패는 손목 회전 습관(한쪽 회전 85% vs 사람 70%)과 K 위치 기억과 관련.

## 한계 및 미확인
