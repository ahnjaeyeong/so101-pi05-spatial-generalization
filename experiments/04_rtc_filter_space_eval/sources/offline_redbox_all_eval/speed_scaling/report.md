# 실행 속도(100/80/60%)와 그리퍼 동기화 오프라인 비교 (2026-10-19)

로봇은 실행하지 않았고, max_relative_target 8, PID, 캘리브레이션도 그대로입니다.
시뮬레이션은 **열린 루프 '시간축 보정' 재생**입니다. 관측을 s배속으로 진행시킨 근사이고, 실제 팔 상태는 P0 서보 모델 v2로 추정했습니다.
그래서 실제 성공률이나 안전성을 보장하지 않습니다.

- **관절 하나하나의 목표 속도는 사람 시연과 비슷합니다.** 정책이 유난히 빠르게 지시한 것은 아닙니다.
- **배포할 때의 팔이 더 느립니다.** 8° 제한과 서보 추종 때문에 lift·elbow가 약 80°/s에서 막힙니다. 데이터를 모을 때 같은 팔로워는 p99 110°/s 이상으로 움직였습니다.
- **작업 단위 타이밍은 사람보다 훨씬 빠릅니다.** 움직임 시작부터 첫 그리퍼 닫힘까지 걸린 시간은 다음과 같습니다(T1). 모두 실제 시간이고, 데이터셋은 타임스탬프 1/30 s, 영상 30 fps라 재생 속도 = 실제 속도입니다.

  |---|---|---|
  | 정책 | **2.24 s** | **0.43 s** |
  | 우리 사람 시연 | 중앙값 7.2 s (p10 4.6) | 3.9 s |
  | 레퍼런스 fixed | 12.3 s (p10 5.6) | 9.9 s |

  레퍼런스 연구의 홍보 영상이 더 빨라 보였다면 배속 편집일 가능성이 큽니다. 데이터 자체는 1배속입니다.

## 2. 실제 첫 파지 실패를 다시 보면
- **T1**: 닫기 명령 순간(2.67 s)의 추종 오차는 **이미 2.8°**였습니다. 큰 오차(36°)는 직전 0.5 s 동안이었고, 팔은 막 도착해 56°/s로 움직이며 3° 정도 지나치던 중이었습니다. 그리퍼는 0.43 s 전에 열기 시작해 21–23°까지만 열렸습니다.
  - 즉 **"팔이 아직 빠르게 움직이고, 그리퍼는 덜 열린 상태에서 닫음"**입니다. 추종 오차만 보고 닫기를 미루는 방식(오차 < 4°)으로는 막을 수 없습니다.
- **T2**: 팔은 닫기 0.3 s 전에 멈췄고 오차는 1° 미만이었습니다. 큐브는 손가락과 정렬되어 있었지만(1–7°) **얕게(손가락 끝) 잡혀** 기울며 빠졌습니다.
  - 재시도의 wrist_roll +40°는 이렇게 돌아간 큐브에 다시 맞춘 것입니다(`wrist_alignment_overlay.png`).
  - **속도 문제가 아니라 목표 자세(깊이)의 정확도 문제**입니다. 감속으로 직접 해결된다는 근거는 없습니다.
  - 폐루프에서 더 오래 가까이 보며 보정할 가능성은 있지만, 오프라인으로는 검증할 수 없습니다.

## 3. 감속 구현 방식 (시뮬레이터 `p0_offline_replay/replay_sim.py` `run_rtc_ts`)
- 30 Hz는 유지하고, 프레임을 건너뛰거나 FPS를 낮추지 않습니다.
- 매 틱 chunk 안의 재생 위치를 s action만큼 전진시키고, 인접한 두 action을 선형 보간해 보냅니다.
- action은 재생 위치가 지나갈 때만 RTC 큐에서 꺼냅니다. 그래서 큐 소비 속도는 s action/틱입니다.
- RTC 지연 추정은 action 단위(지연 × s)로 환산합니다. merge는 lerobot 규칙 그대로입니다.
- 그리퍼도 팔과 같은 재생 위치를 씁니다(sync).
- 현재 lerobot에는 이 기능이 없습니다. 실물에 쓰려면 wrapper에 구현해야 하며, **아직 구현하지 않았습니다.**

## 5. 해석
1. **감속(그리퍼 함께)은 팔 추종과 clamp를 확실히 줄입니다.**
   - clamp 29% → 16%(80%) → 5%(60%)
   - 추종 오차 4.3° → 2.8° → 1.5°
   - 이른 닫힘 8% → 0%
   - 닫을 때 팔 속도 32 → 26 → 20°/s (사람 16°/s)
   - 잡음도 0.55 → 0.30°로 줄어듭니다. 프레임 사이 변화가 보간으로 나뉘기 때문입니다.
   - 대가: 실행 시간 +25% / +67%, 궤적 왜곡 +0.9° / +1.7°
   - 사람 대비 닫는 자세 차(약 9°)는 그대로입니다. **감속이 목표 자세의 정확도를 높이지는 않습니다.**
2. **팔만 늦추면 안 됩니다.** 그리퍼가 사람보다 11–15프레임 일찍 닫힙니다(armonly). 그리퍼는 반드시 팔과 같은 배율로 늦춰야 합니다.
3. **추종 오차 기반 닫힘 대기는 효과가 없거나 해롭습니다.**
   - 100%에서 이른 닫힘이 17%로 오히려 늘고, 자세 차와 시점차도 나빠집니다. 작은 그리퍼 움직임까지 붙잡기 때문입니다.
   - 실제 T1 실패 순간에도 오차는 2.8°라 대기가 작동하지 않았을 것입니다.
4. **T1형 실패**(빠르게 도착하며 덜 열린 채 닫음)는 감속으로 줄어들 여지가 있습니다.
   - 하지만 정책의 연→닫 0.43 s는 80%에서 0.54 s, 60%에서 0.72 s로 늘어날 뿐이고, 사람 최소값(0.97 s)보다 여전히 짧습니다.
5. **T2형 실패**(팔은 멈췄는데 얕게 잡음)는 속도와 무관한 모델 정확도 문제입니다.

## 6. 추천 조합 (아직 구현하지 않음, 실물 미검증)
1. **1순위: 80% 감속, 팔과 그리퍼 같은 배율**(+ 현재 팔 필터, RTC h20 EXP s5)
   - clamp를 절반으로 줄이고 이른 닫힘 0%입니다.
   - 시간 증가(+25%)와 왜곡(1.75°)이 60%보다 작습니다.
2. **2순위: 같은 조합에 '정착 + 열림 유지' 그리퍼 조건 추가**
   - 조건: 팔 속도(lift·elbow)가 약 20°/s 아래이고, 그리퍼가 명령만큼 실제로 열린 상태가 0.3 s 이상 지속될 때만 닫기 허용. 최대 0.5 s까지 기다림.
   - T1형 실패를 직접 겨냥합니다. **다음 단계에서 오프라인 검증이 먼저 필요합니다.**
3. 80%로도 T1형 실패가 남으면 60%를 시험합니다. clamp 5%, 사람과 비슷한 도착 속도를 얻지만 시간이 +67%입니다.
4. T2형(얕은 파지)은 감속이나 동기화로 풀리지 않습니다. 재학습(검증 에피소드 분리, 전체 학습)에서 다룰 과제입니다.
