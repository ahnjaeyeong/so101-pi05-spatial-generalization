# d2 병목 원인 검증 — Expert-only 표본 강화 설계 v2 (2026-10-27)

v1 (`실험설계_v1.md`) 을 사용자 검토 (10-27) 에 따라 고쳤다. 바뀐 점:
- 순서는 A0 → A1 → A2 → A2r → A0′ 이다. A3 는 개별 효과를 본 뒤 실행 여부를 정한다.
- A2r 대조군을 추가했다.
- A3 에 상한을 둔 완화판 (A3c12) 을 추가했다.
- held-out 여부를 데이터마다 표시했다.
- 평가 전용 사람 시연 H 를 추가했다.
- O1 과 O2 를 따로 판정한다.
- 최종 목표에 맞춰 주 지표를 '새 위치에서의 초기 접근' 으로 바꿨다.

**최종 목표 (사용자)**: 기존 위치의 성공률을 올리는 것이 아니다. **새 큐브 위치에서 처음부터 정확한 접근 행동을 만드는 것** 이다.

**이 실험의 질문**: d2 Action Expert 의 roll 조건부 행동 부족 (w_rot ≈ 0, 닫힘 1 s 전 G_tt 0.10 — `action_bottleneck/분석결과.md`) 과 초기 접근 오차가, 학습 표본의 비율 · 희소성 때문인가?
같은 데이터 · 같은 step · 같은 LR 에서 표본 비율만 바꿔 검증한다. d4 를 개선하려는 실험이 아니다.

제약:
- 재학습은 실행하지 않는다 (이 문서는 계획과 비용만).
- LeRobot 코드 · d2/d4 데이터셋 · 체크포인트는 수정하지 않는다.
- d4 학습 (pid 3000922) 을 방해하지 않는다. GPU 작업은 d4 가 끝난 뒤에만 한다.
- 새 파일은 이 폴더에만 만든다.

수치 출처: `s1_design_numbers.py` (CPU, 읽기만) → `s1_design_numbers.json` → `s2_tables.py` → 아래 표.

## 1. 실험 정의와 표본 비율

### 1.1 구간 · 칸 · 가중
- 구간 (판마다):
  - 정지: [0, 움직임 시작)
  - 접근: [움직임 시작, 닫힘 − 3 s)
  - 정렬: [닫힘 − 3 s, 닫힘 + 0.5 s)
  - 닫힘 뒤: 그 이후 끝까지
  - 움직임 시작 = 관절 0–4 중 하나가 첫 프레임 값에서 3° 넘게 벗어난 첫 프레임. 닫힘 = `grasp_train.csv` grasp_f.
- 칸:
  - `vision_probe/labels_v2.csv` 의 roll (15°) × roll 회전 접선 tan (0.5 cm). 라벨 프레임의 ±5 프레임에 붙인다.
  - 정렬 구간 26,880 프레임 중 23,069 (86 %) 에 칸이 있다. 칸이 없는 프레임 (큐브가 wrist 화면 가장자리에 있거나 안 보임) 은 칸 가중 1.

| 실험 | 프레임 가중 (정수) | 바꾸는 요인 |
|---|---|---|
| A0 | 1 | 없음 (추가 4k step 자체의 효과) |
| A1 | 접근 · 정렬 ×3 | 구간 비중 |
| A2 | Random 판 ×2 × 칸 가중 clip(round(40 / 칸의 판 수), 1, 8) | Random 비중 **+** 희소 roll × tan 칸 (두 요인이 섞여 있음) |
| **A2r** (추가) | Random 판 ×2 만 | Random 비중만 (A2 와 같은 K/R 몫) |
| A3 (보류) | A1 × A2 (상한 없음) | 구간 + Random + 칸 |
| **A3c12** (추가, 보류) | min(A1 × A2, 12) | A3 의 완화판 |
| 참고 (계획 없음) | A3c8 · A3c6 (상한 8 · 6), A2m (약한 칸 가중 clip(round(15/n),1,4) × Random 2) | |

{{T1}}

### 1.2 A2 의 섞임과 A2r 로 분리하는 방법
- A2 는 두 가지를 동시에 바꾼다.
  - (i) Random 판 몫: 49.5 → 65.9 % (K 하나당 5.5–7.1 → 3.9–5.1 %)
  - (ii) 희소 roll × tan 칸 몫: 얇음 + 희소 2.0 → 9.7 %
- (i) 만으로도 결과가 바뀔 수 있다. 앞선 진단에서 d2 는 새 위치에서 가까운 K 쪽으로 끌리는 정도 (K 당김) 가 0.22–0.34 였고, K 몫이 줄면 이것이 바뀔 수 있다.
- A2r 은 (i) 만 바꾼다: Random 66.3 %, K 하나당 3.6–4.7 %, 얇음 + 희소 1.9 %.
- 분리 방법:

| 비교 | 추정하는 효과 |
|---|---|
| A2r − A0 | Random/K 비중 효과 |
| A2 − A2r | Random 비중이 같을 때 희소 칸 가중의 효과 (원인 검증의 핵심 비교) |
| A2 − A0 | 두 효과의 합 |

- 칸 가중 단독 (Random ×1) 판은 두지 않았다. 필요하면 'A2c' 로 추가할 수 있다 (11 h).

### 1.3 A3 의 집중 문제와 상한 완화판
- A3 (곱, 상한 없음) 의 문제:
  - 유효 프레임 비율이 0.46 이다.
  - 희소 칸 프레임 평균 노출이 4k step 동안 11.9 회이고, d2 학습까지 합친 누적 최대는 19.0 회다 (A0 6.2).
  - 원인은 Random 판의 희소 칸 정렬 프레임 가중이 3 × 2 × 8 = 48 까지 커지는 것이다.
- 상한을 두면 유효 비율과 노출은 낮아지지만, 칸 대비도 같이 줄어든다:

| 판 | 유효 프레임 비율 | 희소 칸 노출 (4k) · 누적 최대 | 얇음 + 희소 몫 | 접근 + 정렬 몫 |
|---|---|---|---|---|
| A3 (상한 없음) | 0.46 | 11.9 · 19.0 | 13.2 % | 81.5 % |
| A3c12 | 0.67 | 3.7 · 8.9 | 7.2 % | 80.2 % |
| A3c8 (참고) | 0.72 | 2.5 · 7.7 | 5.0 % | 79.5 % |
| A3c6 (참고) | 0.73 | 1.9 · 7.1 | 3.8 % | 79.2 % |

- 완화판으로 A3c12 를 고른 이유:
  - 유효 비율이 A2 (0.66) 와 같다.
  - 칸 몫 7.2 % 가 A2 의 9.7 % 에 가장 가깝다.
  - 노출이 A3 의 1/3 이다.
  - 상한 8 이하에서는 칸 몫이 A2m (약한 가중) 수준까지 떨어진다.
- A3 단계를 실행한다면 A3 와 A3c12 를 둘 다 돌려서 '집중의 대가' 를 비교한다 (8.4 절).

## 2. 희소 roll × 위치 조합 · 기존 데이터에 없는 조합

{{T2}}

- 없음 칸은 (roll 음수, tan ≤ −1 cm) 쪽과 (roll 양수, tan ≥ +1 cm) 쪽에 몰려 있다 (프레임 단위 roll ~ tan 상관 −0.47).
- 평가 정책 프레임 303 개의 분포:
  - 없음 칸 + 표 밖 = 102 개 (34 %). 이 부분은 재표집 (A2 · A3) 으로 표본을 만들 수 없다.
  - 이 부분을 채우려면 새 시연이 필요하다 (예: 닫힘 1–3 s 전에 tan ±1–2 cm 어긋난 상태에서 roll ±30–45° 로 바로잡는 시연). 이 설계의 범위 밖이다.

{{T3}}

- 판 단위로는 위치마다 roll 이 넓게 퍼져 있다. 희소한 것은 roll × 그 순간의 접선 어긋남 (상태) 이다.

## 3. Held-out 여부 — 현재 평가 데이터는 정책 Held-out 이 아니다

**d2 020000 이 256 판 (T1-K · T1-R · T3-K · T3-R) 을 모두 학습했다. 네 실험 모두 이 가중치에서 시작하므로, 현재 있는 사람 시연 데이터 중 정책 기준 held-out 은 없다.** d4 ⊂ d2 이다. 예전 redbox 384 판은 카메라 · 위치가 달라서 쓸 수 없다.

| 평가 데이터 | 정책 기준 | 쓰임 |
|---|---|---|
| d2 256 판 프레임: S1 기울기, 행동 MAE, F1 probe fold | **in-sample (held-out 아님)**. F1 fold 는 probe 용 분할일 뿐 | 참고만. A2/A3 가 더 본 칸의 오차 감소는 근거로 쓰지 않음 |
| G1 반사실 편집 관측 (d2 프레임 기준) | 편집 자체는 학습에 없지만 **기준 프레임은 in-sample** | O2 보조 |
| 평가 롤아웃 프레임 (d2 try3 · filt, 303 QC) | 학습에 없는 상태. 다만 **d2 정책이 만든 상태라 사람 정답이 없다** | O2 보조 (반응 측정) |
| 로봇 KT · RT layout | **학습 위치 (in-sample)** | 기존 위치 성능 확인 |
| 로봇 U layout (UF · UN) | 학습에 없던 layout. 다만 위치는 가장 가까운 학습 큐브에서 2.0–2.8 cm (**보간**) | 새 위치 주 지표 (로봇) |
| **H (새로 녹화)** | **진짜 held-out** (사람 정답 있음, 어떤 학습에도 넣지 않음) | 새 위치 주 지표 (오프라인) |

- 미학습 위치의 한계 (표 4):
  - 학습 위치의 볼록 껍질 안에서 가장 가까운 학습 큐브까지 최대 2.85 cm 다. ≥ 3 cm 인 자리는 없다.
  - 2 cm 는 front 224 px 영상에서 약 7 px (패치 14 px 의 절반) 다.
- 칸 정의와 가중은 학습 라벨 밀도에서만 계산했다. 평가 프레임 수는 표시만 한다. 설계를 고정한 뒤에는 바꾸지 않는다.

## 4. 평가 전용 데이터 H (학습 금지)

### 4.1 내용
- 과제: T1 (빨강 큐브 1 개), 시작 자세 · 녹화 방식 · 카메라는 main_k8 T1 과 같다.
- 위치 · 각도: 표 4 의 U1–U8, 위치마다 각도 2 개 (16 layout) × 2 회 = **32 판**.

| 위치 | 각도 1 (need, 새로움°) | 각도 2 (need, 새로움°) |
|---|---|---|
| U1 | 0 (18.2, 0.2) | 45 (−26.8, 8.3) |
| U2 | 0 (−11.5, 4.8) | 45 (33.5, 20.5) |
| U3 | 0 (4.2, 0.4) | L30 (34.2, 1.7) |
| U4 | L30 (−17.9, 0.4) | R30 (12.1, 1.8) |
| U5 | L30 (−10.3, 0.2) | R30 (19.7, 0.8) |
| U6 | L30 (−3.9, 0.0) | 0 (−33.9, 8.1) |
| U7 | 0 (−28.8, 5.7) | L30 (1.2, 4.6) |
| U8 | 0 (−21.5, 0.8) | 45 (23.5, 0.9) |

- 로봇 평가의 U layout 8 개 (6 절) 는 모두 이 16 개 안에 있다. 그래서 같은 layout 에서 정책과 사람을 비교할 수 있다.
- |need| ≥ 38° (아무 쪽으로 돌려도 되는 범위) 인 조합은 뺐다.
- 녹화는 사용자가 직접 한다 (텔레옵 = 토크 작동). Claude 는 계획 · 명령 시트 · QA 만 한다.
  - U 위치를 계획에 넣는 방법 (새 config 또는 Random 계획 + relabel) 은 녹화 전에 정한다. 기존 config 는 수정하지 않는다.

### 4.2 학습 격리 규칙
1. 저장 위치는 `~/so101_runs/main_k8/heldout_h/`, repo `oxr/so101_k8_heldout_h` 다. 어떤 merge · release 에도 넣지 않는다.
2. launcher 는 `--dataset.root` 가 d2 데이터셋 경로가 아니거나 경로에 `heldout` 이 들어 있으면 시작하지 않는다.
3. H 는 다음에 쓰지 않는다: 가중 · 칸 정의 · LR · step 선택, checkpoint 선택 (항상 4000 step 을 쓴다).
4. H 는 판정 지표 계산에만 쓴다. 모든 정책 (d2 · A0 · A1 · A2 · A2r · A0′ [· A3 · A3c12]) 에 같은 스크립트 · 같은 noise 은행으로 한 번씩 계산한다.
5. 이후 학습에 H 를 넣기로 하면, 그때부터 H 는 held-out 이 아니다. 새 held-out 이 필요하다.

### 4.3 H 로 재는 것
- O1-H: 시작 관측 → 정책 chunk 의 pan · 집게 끝 목표를, 사람의 첫 접근 (닫힘 1 s 전 pan, 닫힘 순간 집게 끝) 과 비교한다.
- O2-H: 닫힘 2.5 · 1.5 · 1.0 s 전 프레임에서 정책의 이후 접선 이동 ~ 라벨 기울기를 사람과 비교한다 (out-of-sample). 같은 프레임으로 G1 반사실 (w_rot, G_tt) 도 잰다.

## 5. 학습 조건 · 구현

### 5.1 같은 조건

| 항목 | 값 |
|---|---|
| 시작 | `--policy.path=<d2>/checkpoints/020000/pretrained_model`, 정규화 통계 = d2 (시작 뒤 normalizer safetensors 를 d2 와 비교) |

| 그 밖 | expert-only, vision 동결, bf16, gradient checkpointing, chunk 50, num_workers 4, image_transforms 끔 (d2 와 같음) |
| 저장 | 2000 · 4000 step. 판정은 **4000 고정** (2000 은 참고) |

{{T5}}

### 5.2 seed
- seed 가 같아도 가중이 다르면 batch 구성은 달라진다. 전역 RNG (noise · t) 열만 같다.
- 그래서 A0 과 A0′ 의 차이를 우연 변동 바닥으로 쓴다.

### 5.3 Weighted Sampler Launcher (승인됨, 아직 만들지 않음)
- `train_weighted.py`:
  - `lerobot.scripts.lerobot_train.EpisodeAwareSampler` 를 가중 sampler 로 바꿔 끼운 뒤 `lerobot_train.main()` 을 실행한다.
  - 가중 sampler 는 index 를 정수 가중만큼 반복하고, epoch 마다 (seed, epoch) 로 randperm 한다.
  - LeRobot 설치 파일과 d2 데이터셋은 수정하지 않는다.
- 입력: `weights_<실험>.npy` (전역 프레임 index 순서, `s1_frames.parquet` 에서 생성) + sha256 기록.
- 시작 전 막는 조건:
  1. d4 pid 가 살아 있음
  2. 데이터셋 경로가 d2 가 아니거나 heldout
  3. output_dir 이 이미 있음
  4. d2 020000 sha256 이 기록과 다름
- CPU 시험 (GPU · 로봇 없음):
  1. 가중이 모두 1 이면 index 순서가 원래 sampler 와 같다.
  2. 10⁶ 번 뽑은 구간 · 칸 · K/R 몫이 표 1 과 ±0.2 %p 안에서 맞는다.
  3. dataloader 가 첫 batch 를 만든다 (모델 적재 없음).

## 6. 로봇 평가 layout (사용자 실행)

T1, 정책당 16 회. 모든 정책이 같은 layout 과 같은 순서를 쓴다 (무작위 순서를 한 번 정해 고정). 실행 설정도 같다 (RTC h20 EXP steps5 queue30, filter 는 한쪽으로 고정).

| 묶음 | layout | 수 | held-out 여부 |
|---|---|---|---|
| KT | K1 · K3 · K6 · K8, 학습에 있던 각도 | 4 | 학습 위치 |
| RT | T1R 판 4 개 위치 · 각도 그대로 (bearing 이 서로 다른 것) | 4 | 학습 위치 |
| UF | U3·0, U4·L30, U6·L30, U8·0 (roll 새로움 ≤ 1°) | 4 | 새 layout, 2–2.8 cm 보간 |
| UN | U2·45, U1·45, U6·0, U7·0 (새로움 5.7–20.5°) | 4 | 새 layout + 덜 익숙한 roll |

- 대상: d2, A0, 그리고 오프라인에서 O1 또는 O2 중 하나라도 통과한 실험.

## 7. 지표 — O1 (초기 접근) 과 O2 (roll 조건부) 를 따로 잰다

### 7.1 O1 초기 접근 정확도 (주 지표, 최종 목표에 직결)

| 이름 | 데이터 | 측정 |
|---|---|---|
| O1-H | H 32 판 시작 관측 (**held-out**) | 정책 chunk 끝 pan − 사람 닫힘 1 s 전 pan (°). 정책 chunk 끝 집게 끝 − 사람 닫힘 순간 집게 끝 (접선 · 반지름 cm) |
| O1-G | 격자 probe (diag exp1, front 영상에서 큐브를 옮긴 시작 관측) | pan − 기대 pan (−bearing − 1.4°) RMS, K 당김 a, 중심 당김 c. 학습 위치 / U 점 따로 |
| O1-R | 로봇 U · KT · RT | 첫 닫힘 1 s 전 pan − 기대 pan, 첫 닫힘 때 FK 집게 끝 − 큐브 (접선 · 반지름) |

### 7.2 O2 wrist roll 조건부 행동 정확도

| 이름 | 데이터 | 측정 |
|---|---|---|
| O2-H | H 닫힘 2.5 · 1.5 · 1.0 s 전 (**held-out**) | 정책 이후 접선 이동 ~ tan 라벨 기울기 / 사람 기울기, G1 반사실 w_rot · G_tt |
| O2-G | d2 T1 128 판 (in-sample 기준 프레임) + 평가 롤아웃 프레임 | G1: w_rot, G_tt, G_rr, roll Δ 별 G |
| O2-R | 로봇 U | 첫 닫힘 wrist tan 오차, |need| < 15° / 15–38° 별. tan 오차 ~ roll 기울기. 손목 정렬 오차 (turn − need) |

### 7.3 결과 · 감시
- 결과: 첫 파지 성공, 최종 성공, 걸린 시간 (참고).
- O3 과적합 감시: 칸 등급별 in-sample flow loss (고정 noise · t). 희소 칸 감소 / 보통 칸 감소 ≥ 2 이면 '외움 의심' 으로 표시한다.

## 8. 판정 기준 (결과 전에 고정)

### 8.1 공통
- 효과 = X − A0. 둘 다 같은 4k 추가 step 이다. d2 대비는 참고로만 쓴다.
- δ_m = |A0′ − A0| (지표 m 마다).
- 신뢰구간은 판 (H 는 판, 로봇은 layout) 묶음 bootstrap 95 % 이다.

### 8.2 O1 개선 (X vs A0) — 아래를 모두 만족
1. O1-H pan 오차 RMS 가 max(1.5°, 2δ) 이상 줄고, CI 가 0 을 넘지 않는다 (감소 쪽).
2. O1-H 집게 끝 접선 오차 중앙값이 max(0.5 cm, 2δ) 이상 준다.
3. O1-G 에서 U 점 K 당김 a 가 늘지 않는다.
4. 로봇 확인 (O1-R): U 8 layout 의 첫 닫힘 집게 끝 접선 오차를 짝 Wilcoxon 한쪽 p < 0.05 로 비교한다. 중앙값 감소 ≥ 0.5 cm.

### 8.3 O2 개선 (X vs A0) — 아래를 모두 만족
1. O2-G w_rot (닫힘 1.0 · 1.5 s 평균) 이 max(0.2, 2δ) 이상 오르고, CI 가 0 보다 크다.
2. O2-H 정책/사람 접선 기울기 비가 max(0.15, 2δ) 이상 오르거나, O2-G G_tt (닫힘 1.0 s) 가 max(0.05, 2δ) 이상 오른다.
3. 로봇 확인 (O2-R): U 의 첫 닫힘 |wrist tan 오차| 중앙값이 ≥ 0.3 cm 줄고 (짝 Wilcoxon 한쪽 p < 0.05), tan 오차 ~ roll 기울기가 0 쪽으로 간다.

- 공통 악화 조건: G_rr 감소 > 0.05, 보통 칸 loss 증가 > 5 %, KT · RT 첫 파지 성공이 A0 보다 3 판 이상 적음. 이 중 하나라도 해당하면 '개선 + 악화' 로 따로 적는다.

### 8.4 결과 보고 — 실험마다 4 칸으로 나눠 적는다 (합치지 않음)

| | O2 개선 | O2 없음 |
|---|---|---|
| **O1 개선** | 둘 다 | O1 만: 시작 목표 (front 영상 → pan) 는 나아졌지만, 마지막 정렬이 roll 에 맞춰지지 않음 |
| **O1 없음** | O2 만: 늦은 보정은 나아졌지만, 새 위치의 첫 접근 목표는 그대로 | 효과 없음 |

원인 해석 규칙:

| 관측 | 해석 |
|---|---|
| A2 − A2r 에서 O2 개선 | 희소 roll × tan 칸이 roll 조건부 부족의 원인 (가설 지지) |
| A2r − A0 에서 O1 개선, A2 − A2r 에서 O1 없음 | 초기 접근 개선은 Random/K 비중 효과 |
| A1 − A0 에서 O1 또는 O2 개선 | 구간 비중 (접근 · 정렬 표본 수) 효과 |
| 모두 없음 (δ 안) | 기존 데이터 재표집으로는 바뀌지 않음 → 새 위치 · 없음 칸을 채우는 새 시연, 또는 Expert 용량 · 학습 방식 |

A3 단계 결정 (A0′ 까지 끝난 뒤):
- A1 과 A2 (또는 A2r) 가 **서로 다른 칸** 에서 개선되면 (예: A1 은 O1, A2 는 O2) A3 와 A3c12 를 실행한다. 두 효과가 합쳐지는지, 그리고 상한이 효과를 깎는지 본다.
- 하나만 개선되거나 둘 다 없으면 A3 는 실행하지 않는다.
- A3 와 A3c12 의 판정 기준은 위와 같다. 둘 다 통과하면 O3 외움 의심이 없는 쪽 (보통 A3c12) 을 다음 단계 후보로 둔다.

## 9. 예상 비용

### 9.1 GPU (d4 가 끝난 뒤에만)
- 학습 1 회 = 4000 × 9.92 s (d2 단독 속도) ≈ 11.0 h + 적재 · 저장 약 0.1 h.
- 오프라인 평가는 checkpoint (4000) 하나에 약 1.5 h 로 추정한다.
  - 내역: 모델 적재 3 분, G1 128 판 약 48 분 (10-27 g1c 96 판 37 분에서 비례), 격자 probe 5 분 (exp1 실측 281 s), 평가 롤아웃 프레임 · H · O3 약 30 분.
  - d2 020000 도 H · O3 를 새로 재야 해서 1 회 포함한다.
  - 학습 사이사이에 돌려 중간 결과를 본다.

| 단계 | 내용 | GPU 시간 | d4 종료 10-29 03:00 시작 기준 끝나는 시각 |
|---|---|---|---|
| 1 | A0 학습 + 평가 (+ d2 평가) | 11.1 + 3.0 | 10-29 ~17:00 |
| 2 | A1 학습 + 평가 | 12.6 | 10-30 ~06:00 |
| 3 | A2 학습 + 평가 | 12.6 | 10-30 ~18:30 |
| 4 | A2r 학습 + 평가 | 12.6 | 10-31 ~07:00 |
| 5 | A0′ 학습 + 평가 | 12.6 | 10-31 ~20:00 |
| 소계 | 5 학습 + 6 평가 | **약 65 h** | |
| (보류) 6 | A3 · A3c12 학습 + 평가 | 25.2 | 11-01 ~21:00 |
| 합계 (A3 포함) | | 약 90 h | |

- 2000 step checkpoint 도 평가하면 실험당 +1.5 h 다 (선택).
- d4 속도가 바뀌면 시작 시각도 같이 밀린다. GPU 는 d4 가 끝난 것을 확인한 뒤에만 쓴다.

### 9.2 디스크
- checkpoint 하나 11 GB (모델 8.8 + optimizer 2.2). 실험당 2 개 = 22 GB.
- 5 실험 110 GB, A3 포함 154 GB. 현재 남은 공간 410 GB.

### 9.3 사람 · 로봇 시간 (사용자)

| 일 | 예상 |
|---|---|
| H 녹화 32 판 (판당 15–25 s + 배치) + QA 확인 | 약 1–1.5 h. GPU 학습과 동시에 해도 됨 (로봇 · 카메라만 씀) |
| 로봇 평가 16 회 × 정책 (d2 · A0 + 통과 실험, 최대 6) | 정책당 약 35–45 분 → 최대 약 4.5 h |

### 9.4 CPU 작업 (Claude, 승인 뒤)
- launcher + CPU 시험 + 가중 파일: 약 1–2 h.
- 평가 스크립트 묶음 (O1-H · O2-H 새로, G1 · 격자 · O3 재사용): 약 2–3 h.
- H 계획 · 명령 시트 · QA: 약 1 h.
- 모두 d4 와 경합하지 않는 CPU 작업이다 (`nice`).

## 10. 보호 조치
- d2 · d4 데이터셋 · 체크포인트는 읽기만 한다. d2 020000 `model.safetensors` · `optimizer_state.safetensors` sha256 을 시작 전에 기록하고, 각 실험 뒤 다시 확인한다.
