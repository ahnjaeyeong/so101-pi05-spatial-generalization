# d2 병목 원인 검증 — Expert-only 표본 강화 A0–A3 설계 (2026-10-27)

목적: d2 `checkpoints/020000` 을 공통 시작점으로 하고, **같은 데이터 · 같은 step · 같은 LR** 에서 **표본 비율만** 바꾼다.
이렇게 해서 Action Expert 의 roll 조건부 행동 부족이 학습 표본의 희소성 때문인지 검증한다.
d2 에서 잰 값은 w_rot ≈ 0 (−0.18…−0.01), G_tt 0.10 (닫힘 1 s 전) 이다 (`action_bottleneck/분석결과.md`). d4 를 개선하려는 실험이 아니다.

| 실험 | 내용 |
|---|---|
| A0 | 기존 데이터, 균일 표집, 같은 step 추가 학습 (추가 step 자체의 효과를 통제) |
| A1 | 접근 · 정렬 구간 가중 |
| A2 | Random 판 + 희소 roll × tan 칸 가중 |
| A3 | A1 × A2 |

제약 (사용자 10-27):
- 재학습은 시작하지 않는다.
- d2 / d4 데이터셋 · 체크포인트는 수정하지 않는다 (읽기만).
- 실행 중인 d4 학습 (pid 3000922) 은 건드리지 않는다.
- 새 파일은 이 폴더 `d2/sampling_ablation/` 에만 만든다.

수치는 모두 스크립트에서 나온다: `s1_design_numbers.py` (CPU, 읽기만) → `s1_design_numbers.json` → `s2_tables.py` → 아래 표.

## 0. 설계 요약

| 항목 | 설계 |
|---|---|
| 시작점 | d2 020000 가중치. **새 fine-tune** (optimizer · scheduler 새로 시작, 4 절), 네 실험 모두 같음 |
| 가중 방식 | d2 데이터셋을 그대로 쓰고, 프레임 정수 가중 sampler 를 쓴다 (새 launcher 파일, lerobot 파일은 수정하지 않음, 5.3 절). A0 = 모든 가중 1 |

| GPU | d4 가 끝난 뒤 (10-27 17:10 step 8,155 · 10.3 s/step → ETA 10-29 ~03:00) 에만. d4 와 동시에 돌리지 않는다 |

## 1. 실험별 표본 비율과 실제 유효 표본 수

### 1.1 정의
- 구간 (판마다):
  - 정지: [0, 움직임 시작)
  - 접근: [움직임 시작, 닫힘 − 3 s)
  - 정렬: [닫힘 − 3 s, 닫힘 + 0.5 s)
  - 닫힘 뒤: 정렬 이후 끝까지
  - 움직임 시작 = 관절 0–4 중 하나가 첫 프레임 값에서 3° 넘게 벗어난 첫 프레임.
  - 닫힘 = `grasp_train.csv` 의 grasp_f (check_dataset.first_grasp 규칙).
- 칸:
  - `vision_probe/labels_v2.csv` 의 roll · tan 라벨을 쓴다 (10 프레임 간격, probe_ok, roll 회전 접선 라벨). 라벨 프레임의 ±5 프레임 안 프레임에 붙인다.
  - roll 은 15° 칸, tan 은 0.5 cm 칸.
  - 정렬 구간 26,880 프레임 중 23,069 (86 %) 에 칸이 있다. 나머지 (큐브가 wrist 화면 가장자리에 있거나 안 보임) 는 칸 가중 1.
- 가중 (프레임마다 정수):

| 실험 | 가중 |
|---|---|
| A0 | 1 |
| A1 | 접근 · 정렬 프레임 ×3, 나머지 1 |
| A2 | (Random 판이면 ×2) × 칸 가중 clip(round(40 / 칸의 판 수), 1, 8). 칸 가중은 정렬 구간 중 칸이 있는 프레임에만, 나머지는 1 |
| A3 | A1 가중 × A2 가중 (곱, 상한 없음 = 2×2 요인 설계) |
| 참고 (실행 계획 없음) | A2r: Random ×2 만. A2m: 약한 칸 가중 clip(round(15 / n), 1, 4) × Random 2. A3m: min(A1 × A2m, 8) |

- 유효 표본 수는 Kish 식 (Σw)² / Σw² 로 잰다.
  - 프레임 단위와, 판 안 가중을 합친 판 단위로 따로 잰다.
  - 판 안 프레임끼리는 강하게 상관하므로, 실질적인 독립 단위는 판 (256 개) 이다.

{{T1}}

### 1.2 수치에서 확인되는 점 (설계 근거)
- A1: 접근 + 정렬 몫이 55.2 → 78.7 % 로 오르고, 닫힘 뒤 몫은 36.1 → 17.2 % 로 내려간다. 유효 판 수는 거의 그대로다 (248 → 246).
- A2 의 칸 가중을 약하게 하면 (A2m) 얇음 + 희소 칸 몫이 2.0 → 4.4 % 에 그친다. A2 는 2.0 → 9.7 % 까지 올린다.
  - 10 % 를 넘기면 희소 칸 프레임이 4k step 안에서 평균 9 회 이상 뽑힌다 (d2 학습까지 합친 누적은 15 회 이상).
- A2 는 K 판 몫도 50 → 34 % 로 줄인다 (K 하나당 5.5–7.1 → 3.9–5.1 %).
  - 그래서 diag 에서 잰 K 당김 (0.22–0.34) 이 줄어드는 효과와 섞인다. 이 둘은 8 절 판정에서 분리한다.

## 2. 희소 roll × 위치 조합, 그리고 기존 데이터에 없는 조합

{{T2}}

- 없음 칸은 (roll 음수, tan ≤ −1 cm) 쪽과 (roll 양수, tan ≥ +1 cm) 쪽에 몰려 있다 (프레임 단위 roll ~ tan 상관 −0.47, `c5_coverage.json`).
- 평가 정책 프레임 303 개의 분포:
  - 없음 칸 17 + 표 밖 85 = 102 개 (34 %). 이 부분은 재표집 (A2) 으로 표본을 만들 수 없다.
  - A2 가 직접 늘리는 희소 칸에는 52 개 (17 %) 가 있다.
- 기존 데이터에 없는 조합을 채우려면 새 시연이 필요하다 (이 설계의 범위 밖, 표시만 함).
  - 예: 닫힘 1–3 s 전에 tan 이 ±1–2 cm 어긋난 상태에서 roll ±30–45° 로 바로잡는 시연.

판 단위로 보면 (큐브 방향 × 닫힘 roll), 위치마다 roll 이 이미 넓게 퍼져 있다:

{{T3}}

- 0 인 칸은 대부분 |roll| > 45° 이거나 Random 판이 드문 방향이다.
- 표 4 의 미학습 위치 후보에서도 같은 위치 5 cm 안 학습 판들의 roll 과 15° 이상 다른 조합은 U2·45 (20.5°) 와 U1·L30 (23.3°, 그러나 need −41.8° 로 '아무 쪽' 범위) 둘뿐이다.
- 따라서 희소한 것은 '위치 × roll' 이 아니라 **'roll × 그 순간의 접선 어긋남 (상태)'** 이다.

## 3. 기존 데이터 복제 (가중) 의 과적합 위험과 데이터 누출

### 3.1 과적합
- 판 · 위치 단위:
  - K 는 8 곳이고 각 K 에 16 판 (T1K 8 + T3K 8) 이 있다.
  - A1 은 K 몫을 바꾸지 않고, A2/A3 은 K 몫을 줄인다. 따라서 K 위치 과적합 위험은 늘지 않는다.
  - Random 판은 판마다 위치가 다르다. ×2 는 128 개 위치를 고르게 두 배로 할 뿐이다 (판 하나의 최대 몫 1.0–1.1 %, 상위 10 판 8.4–9.4 %).
- 주된 위험은 프레임 단위 집중이다.
  - A2: 희소 칸 프레임 (25 판) 이 4k step 동안 평균 8.7 회 뽑히고, d2 학습까지 합친 누적 최대는 15.2 회다 (A0 은 6.2).
  - A3: 같은 값이 11.9 회 / 19.0 회다.
  - 이 프레임들은 사람이 어긋난 자세를 바로잡는 짧은 구간이다. 그 판의 궤적 자체를 외울 수 있다.
- 감시 지표 O3 (7.4 절):
  - 칸 등급별 in-sample flow loss 를 잰다 (고정 noise · 고정 t, 2000 · 4000 step).
  - 희소 칸 loss 감소가 보통 칸 감소의 2 배 이상인데 O2 (반사실 roll 지표) 에 변화가 없으면 '외움' 으로 판정한다.

### 3.2 데이터 누출
1. d2 20k 가 이미 256 판을 모두 학습했다. 그래서 네 실험 모두 사람 시연 기준의 held-out 이 없다.
   - d4 ⊂ d2 이다. 예전 redbox 384 판은 카메라 · 위치가 달라서 쓸 수 없다.
   - 따라서 오프라인 행동 MAE · 정책/사람 기울기 (S1) 는 모두 in-sample 이다.
   - A2/A3 는 희소 칸 프레임을 더 많이 봤으므로, **그 칸의 in-sample 오차 감소는 개선 근거로 쓰지 않는다.**
2. 개선 근거로 쓰는 측정:
   - (a) 반사실 편집 반응 G1 (w_rot, G_tt): 편집된 관측은 학습 라벨에 없다. 다만 기준 프레임은 in-sample 이다.
   - (b) 평가 정책 프레임 (try3 · filt): 학습에 없는 상태다.
   - (c) 로봇 평가.
3. 칸 정의와 가중은 학습 라벨 밀도에서만 계산했다.
   - 평가 프레임 수는 표 2 에 표시만 하고 가중에는 쓰지 않았다.
   - 설계를 고정한 뒤에는 가중을 바꾸지 않는다 (평가 결과를 보고 가중을 고르는 선택 누출 방지).
4. F1 probe fold 는 probe 용 분할이다. 정책 입장에서는 held-out 이 아니다.
5. '미학습 위치' 의 한계 (표 4):
   - 학습 위치의 볼록 껍질 안에서, 가장 가까운 학습 큐브까지의 거리는 최대 2.85 cm 다. ≥ 3 cm 인 자리는 없다.
   - 2 cm 는 front 224 px 영상에서 약 7 px 로, 패치 (14 px) 의 절반이다.
   - 따라서 위치 기준의 '미학습' 은 2–2.8 cm 보간 시험이다. 그래서 roll 조합의 새로움을 함께 기록한다.
6. 선택 사항: 깨끗한 오프라인 held-out 이 필요하면 새 사람 시연 H 를 녹화한다 (예: T1-R 24 판, 표 4 위치 · 각도). H 는 어떤 학습에도 넣지 않는다. 녹화는 사용자가 한다. H 가 없으면 오프라인 판정은 2 의 측정으로만 한다.

## 4. 재개 (optimizer/scheduler state 이어받기) vs 새 fine-tune

lerobot 0.6.2 코드 (`scripts/lerobot_train.py`, `configs/train.py`, `optim/schedulers.py`) 와 d2 020000 `training_state/` 에서 확인한 내용:

| 항목 | 재개 `--resume=true --config_path=<020000>/pretrained_model/train_config.json` | 새 FT `--policy.path=<020000>/pretrained_model` |
|---|---|---|
| 가중치 | d2 020000 | 같음 |
| AdamW m · v (2.2 GB) | 이어받음 | 0 에서 시작 (bias correction) |
| scheduler | last_epoch 20000 에서 이어가지만 lambda 는 새 `--steps` 로 다시 만든다. R1: LR 이 2.5e-6 → 4.0e-6 으로 뛰었다가 다시 2.5e-6 으로 내려감. R2 (`--scheduler.num_decay_steps=20000`): 2.5e-6 고정 | 새 warmup + cosine (표 5 의 F1–F3) |
| RNG · 데이터 순서 | d2 rng_state + `compute_sampler_state(step, len(sampler))` 로 정한 위치. 데이터 길이나 가중이 바뀌면 이 위치는 의미가 없다 | seed 로 새로 시작 |
| 정규화 통계 | 체크포인트에 저장된 값 (d2) 이 우선 | `dataset.meta.stats` 로 덮어쓴다. d2 데이터셋을 그대로 쓰면 같은 값 (시작 뒤 normalizer safetensors 를 비교해 확인) |
| 출력 폴더 | train_config 의 output_dir = **d2 학습 폴더**. `--output_dir` 을 주지 않으면 d2 의 `checkpoints/` 에 024000 · last 링크를 쓴다 (redbox_all 30k 재개가 실제로 그렇게 씀) | 새 폴더가 필수 (이미 있으면 오류) |
| 설정 | d2 train_config 를 그대로 쓴다. 가중 sampler 를 쓰려면 어느 쪽이든 launcher 가 필요하다 | 네 실험을 같은 CLI 로 맞출 수 있다 |

- Adam 상태 차이의 크기: β1 0.9 · β2 0.95 이므로 반감기가 m 6.6 step, v 13.5 step 이다.
  - 약 100 step 뒤에는 이어받은 상태의 영향이 거의 사라진다.
  - 그래서 두 방식의 실질적인 차이는 **LR 곡선과 데이터 순서** 다.

{{T5}}

- 참고 기록: redbox_all 20k → 30k 재개 (2.5e-6 × 10k step, 적분 0.025 ≈ d2 형 20k 의 9 %) 뒤 로봇 첫 파지가 55 → 30 % 로 바뀌었다 (space eval, 40 판).
  - 이 크기의 추가 학습도 로봇 행동을 바꾼다는 기록이다. F1 의 적분 0.024 가 같은 크기다.
- 선택: **새 FT · F1**. 이유:
  1. R2 는 적분이 3.7 % 라서, 결과가 '변화 없음' 이면 표본 효과가 없어서인지 LR 이 부족해서인지 구분할 수 없다.
  2. F2 는 d2 학습의 20 % 에 해당한다. A0 자체가 크게 움직여 (망각, K 당김 변화) 비교 잡음이 커진다.
  3. 재개는 d2 폴더에 쓸 위험이 있고, sampler 위치가 가중 sampler 와 맞지 않는다.
- 재개를 쓰기로 하면 지킬 것:
  - 020000 을 새 폴더로 복사한 뒤, 사본의 train_config 로 재개한다.
  - `--output_dir` 은 새 폴더로 준다.
  - `--scheduler.num_decay_steps=20000` (R2) 를 준다.

## 5. 같은 학습 조건

### 5.1 고정 값

| 항목 | 값 |
|---|---|
| 시작 가중치 | d2 020000 (`--policy.path`), 정규화 통계 = d2 |
| LR | F1: `--policy.optimizer_lr=1e-5 --policy.scheduler_warmup_steps=200 --policy.scheduler_decay_steps=4000 --policy.scheduler_decay_lr=2.5e-6` (steps = decay_steps 라서 자동 축소 없음) |
| optimizer | AdamW β (0.9, 0.95), wd 0.01, grad clip 1.0 (d2 와 같음) |
| step · batch | 4000 · 32 = 128,000 표본 (≈ d2 1.04 epoch). d2 단독 속도 9.92 s/step 기준 ≈ 11 h/실험 |
| seed | 2001 (모든 실험) + A0 은 2002 로 한 번 더 (A0′) |
| 그 밖 | expert-only, vision 동결, bf16, gradient checkpointing, chunk 50, num_workers 4, image_transforms 끔, cudnn_deterministic False (모두 d2 와 같음) |
| 저장 | 2000 · 4000 step. checkpoint 하나 11 GB (모델 8.8 + optimizer 2.2) → 실험당 22 GB, 5 실험 110 GB (남은 디스크 410 GB) |

### 5.2 seed 의 의미
- seed 가 같아도 가중이 다르면 batch 구성은 달라진다. 전역 RNG (flow-matching noise · t) 열만 같다.
- 그래서 A0 (2001) 과 A0′ (2002) 의 차이를 '같은 조건에서의 우연 변동' 의 바닥 δ 로 쓴다 (8 절).

### 5.3 가중 sampler (승인 뒤 구현)
- `train_weighted.py`:
  - lerobot 파일은 수정하지 않는다. `lerobot.scripts.lerobot_train.EpisodeAwareSampler` 를 가중 sampler 로 바꿔 끼운 뒤 `lerobot_train.main()` 을 실행한다.
  - 가중 sampler 는 index 를 정수 가중만큼 반복하고, epoch 마다 (seed, epoch) 로 randperm 한다.
  - 가중 파일은 `weights_A*.npy` (전역 프레임 index 순서).
  - d4 pid 가 살아 있으면 시작하지 않는다.
- CPU 시험 (GPU · 로봇 없이):
  1. 가중이 모두 1 이면 index 순서가 lerobot 원래 sampler 와 같다.
  2. 10⁶ 번 뽑은 구간 · 칸 몫이 표 1 과 ±0.2 %p 안에서 맞는다.
  3. 정규화 통계가 d2 와 같다.
- 채택하지 않은 방식:
  - 파생 데이터셋 (`lerobot-edit-dataset merge` 로 판 복제): 판 단위 가중만 된다. A1 구간 가중을 하려면 영상을 재인코딩한 구간 사본이 필요하다. 이 사본은 마지막 가중 프레임보다 50 프레임 뒤까지 포함해야 chunk padding 이 원본과 같아진다. 또 merge 통계가 d2 와 달라질 수 있다.
  - lerobot 내장 `sample_weighting`: rabc · uniform 만 있다. 손실 가중이라 batch 분산도 커진다.

### 5.4 순서 · 일정
1. d4 가 끝난 뒤 시작한다.
2. 1단계: A0 (2001) → A3 (2001) → A0′ (2002), 약 34 h. 그 뒤 오프라인 평가 (O1–O3, checkpoint 하나에 약 1.2 h).
3. A3 가 A0 대비 8 절 오프라인 기준을 통과하면 2단계: A1, A2 (약 22 h).
4. A3 가 통과하지 못하면 A1/A2 는 생략한다. 이 경우 '기존 데이터 재표집으로는 바뀌지 않음' 으로 판정한다.

## 7. 지표 — 초기 접근 목표와 wrist roll 조건부 행동을 따로 잰다

### 7.1 초기 접근 목표 정확도
- O1 (오프라인, 시작 관측): diag exp1 격자 probe 를 쓴다 (`diag_grasp_bias/exp1_ckpt_grid.py`, 같은 noise 은행).
  - front 영상에서 큐브를 격자 위치로 옮긴 시작 관측을 넣고, chunk 끝 pan 을 pan 기대값 (−bearing − 1.4°) 과 비교한다.
  - 지표: 오차 RMS, K 당김 a, 중심 당김 c. 학습 위치와 U 점 (≥ 2 cm) 은 따로 낸다.
- R1 (로봇): 첫 닫힘 1.0 s 전의 pan − pan 기대값, 그리고 첫 닫힘 때 FK 집게 끝 − 큐브의 접선 · 반지름 (cm).

### 7.2 wrist roll 조건부 행동 정확도
- O2 (오프라인): G1 roll 요인 실험을 그대로 쓴다 (`action_bottleneck/g1_roll_factorial.py`).
  - 대상: T1 128 판 × 닫힘 2.5 · 1.5 · 1.0 s 전 프레임, 같은 noise 4 개.
  - 지표: w_rot, G_tt, G_rr, roll Δ 별 G.
  - 같은 측정을 평가 정책 프레임 (try3 · filt) 에도 적용한다 (학습에 없는 상태).
- S1 정책/사람 기울기 비는 in-sample 이라 참고로만 쓴다.
- R2 (로봇):
  - 첫 닫힘 때 wrist 영상 큐브의 tan 오차 (roll 회전 라벨) 를 |need| < 15° 와 15–38° 로 나눠 낸다.
  - tan 오차 ~ roll 기울기를 잰다 (roll 을 반영한다면 0 에 가깝다).
  - 손목 정렬 오차 (turn − need) 를 잰다.

### 7.3 결과 지표
- 첫 파지 성공, 최종 성공 (상자 안), 걸린 시간.

### 7.4 과적합 감시 O3
- 칸 등급 (보통 · 얇음 · 희소) 별 in-sample flow loss 를 잰다 (고정 noise · t, 판 묶음 bootstrap).
- 2000 · 4000 step checkpoint 에서 잰다.

## 8. 판정 기준 (결과를 보기 전에 고정)

비교 대상:
- 표본 효과 = X − A0 (같은 추가 step 을 했으므로 추가 학습 효과가 상쇄됨).
- d2 대비는 참고로만 쓴다 (추가 학습 효과가 섞여 있음).
- 같은 조건의 변동 바닥: 지표 m 마다 δ_m = |A0′ − A0|.

**오프라인 '개선' (X vs A0)** — 아래를 모두 만족해야 한다:
1. w_rot (닫힘 1.0 · 1.5 s 전 평균) 이 max(0.2, 2δ) 이상 오르고, 판 묶음 bootstrap 95 % CI 가 0 보다 크다. (d2: −0.18 · −0.09, roll 을 반영한다면 1)
2. G_tt (닫힘 1.0 s 전) 가 max(0.05, 2δ) 이상 오르고, CI 가 0 보다 크다. (d2 0.10, 사람 state 기준 0.14)
3. 평가 정책 프레임 O2 에서도 방향이 같다 (CI 가 반대 방향으로 0 을 넘지 않는다).
4. 악화가 없다: G_rr 감소 ≤ 0.05, 보통 칸 in-sample loss 증가 ≤ 5 %, O1 pan 오차 RMS 증가 ≤ 1°.
5. 외움이 아니다: 희소 칸 loss 감소 / 보통 칸 loss 감소 < 2. 이 비가 2 이상이면 1 · 2 를 통과해도 '외움 의심' 으로 따로 표시한다.

**로봇 '개선' (X vs A0, 같은 16 layout 짝 비교)**:
- 주 지표: 첫 닫힘 |tan 오차|.
  - U 묶음 8 개와 전체 16 개 각각에서, 짝 Wilcoxon 한쪽 p < 0.05 이고 중앙값이 0.3 cm 이상 줄어야 한다.
  - 0.3 cm 는 wrist 라벨 바닥 0.29–0.43 cm 에 해당한다.
- 부 지표: 첫 파지 성공을 exact McNemar 로 본다.
  - 16 짝에서 양쪽 p < 0.05 가 되려면 불일치 6 쌍 이상이 모두 한 방향이어야 한다. 큰 차이만 검출된다 (참고).
- roll 조건부: R2 의 tan 오차 ~ |need| 기울기가 A0 보다 0 에 가까운지, 부호와 크기를 보고한다.

**원인 해석 규칙**:

| 관측 | 해석 |
|---|---|
| A2 (및 A3) 통과, A1 미통과 | 희소 roll × tan 조합이 원인이라는 가설 지지 |
| A1 만 통과 | 구간 비중 (접근 · 정렬 표본 수) 문제 |
| A2 의 개선이 O1 (K 당김 · pan) 에만 있고 O2 (w_rot) 에는 없음 | Random/K 비중 효과 (roll 조합 아님). 분리가 필요하면 A2r 추가 |
| 모두 미통과 | 기존 데이터 재표집으로는 바뀌지 않음 → 없음 · 표 밖 칸 (평가 프레임 34 %) 을 채우는 새 시연, 또는 Expert 용량 · 학습 방식 |
| 상호작용 | A3 − A1 − A2 + A0 (2단계까지 갔을 때만) |

## 9. 보호 조치

  - 시작 전에 d2 020000 `model.safetensors` · `optimizer_state.safetensors` 의 sha256 을 기록하고, 실험마다 끝난 뒤 다시 비교한다.

- 로봇 명령은 사용자가 입력한다.

## 10. 사용자 결정이 필요한 항목
1. 가중 sampler launcher (새 파일, lerobot 수정 없음) 를 써도 되는지. 아니면 판 단위 복제 (A1 불가) 로 줄일지.
2. LR: F1 (새 FT, 권장) 또는 R2 (재개, 2.5e-6 고정).
3. 단계 진행 (A0 + A3 + A0′ 먼저) 또는 네 실험 한꺼번에 (+ A0′, 약 56 h).
4. held-out 사람 시연 H 를 녹화할지.
5. 로봇 평가 filter on/off (d2 기존 평가와 같은 쪽으로 고정).
