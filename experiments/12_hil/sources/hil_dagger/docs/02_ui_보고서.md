# HIL 수집자 화면 (Collector Mode) — 구현 · 가짜 장치 검증 (2026-11-04)

근거 표시: **[코드]** 로컬 코드 확인 · **[가짜]** 가짜 장치 / 미리보기 검증 · **[미검증]** 실물 미검증.

실행 제한 준수:
- 실물 SO-101 · 리더 · 카메라 연결 없음. 시험은 `/nonexistent` 장치 경로를 쓰고 `MOCK_OK` assert 를 통과했다.
- 정책 추론 · 녹화 · GPU 학습 없음. 정책은 stub 이고 `CUDA_VISIBLE_DEVICES=""` 로 돌렸다.
- rft01 · eval chain 은 건드리지 않았다. 보고 시점에 rft01 은 998/1000 step 이었다.
- 성능 측정은 학습과 같은 기계에서 함께 돌았다.

## 1. 구조 — 표시 전용, 제어와 분리

```
lerobot 0.6.2 dagger (변경 없음) ─┐
hil_dagger_entry.py adapter ─────┤ A12 tap 스레드 (10 Hz, 읽기만): /dev/shm/hil_<tag>_<pid>/state.json · wrist.npy · front.npy
                                 │
hil_viewer.py (별도 프로세스, python3) ─ hil_ui_state.derive() → hil_ui_render.render() (PIL 한 장) → Tk 창
```

- **제어 · 안전 로직은 바꾸지 않았다.** adapter 변경은 기록용 bookkeeping 과 tap 스레드뿐이다. `git diff main` 에서 지운 줄은 5 줄로, 모두 기본값 dict · 반환문 래핑 · 로그 줄이다.
  - 리더 토크 함수와 전환 함수는 원래 함수를 그대로 부르고, 상태만 덧붙여 기록한다.
  - 변경하지 않은 것: RTC 큐 처리, A10 정책 오류 차단, 단일 writer, 리더 동기화, 8° clamp, 팔 필터 OFF, 자동 복귀 없음, 데이터 형식.
- **키를 받지 않는다.** 실시간 창에는 키 바인딩이 없다. 바인딩은 `<FocusIn>`·`<FocusOut>` 둘뿐이고 [가짜] `--smoke` 로 확인했다.
  - 창에 포커스가 오면 "이 창에서는 키가 동작하지 않습니다 — 터미널을 클릭" 띠를 그린다.
  - 키는 공식 터미널 리스너 하나만 받는다. 실물 명령을 내는 버튼은 없다.
- **화면 상태는 실제 제어 사실값으로만 정한다** (`hil_ui_state.derive`):
  - 쓰는 값: phase, 대기 키, 전환 진행, 리더 토크 호출 기록, RTC 스레드 `_policy_active`, 정지 뒤 정책 명령 여부, 오류 래치, 종료 메뉴.
  - 상태가 1 s 넘게 갱신되지 않으면 "상태 확인 불가" 로 표시한다.
  - 값이 없거나 맞지 않으면 "제어권 미확인" 으로 표시하고 조작을 유도하지 않는다.
- **"사람 제어 준비 완료" 는 아래가 모두 참일 때만 표시한다:**
  - phase = paused, 전환이 끝남, 직전 전환 = 정책 → 정지
  - RTC 스레드 꺼짐이 **확인됨** (False). None 이면 불가
  - 정지 뒤 정책 명령 0, 리더 토크 켜짐
  - 정렬 이동이 끝난 뒤 0.3 s 가 지남 (서보가 멈출 시간, 화면 규칙)

## 3. 화면 구성

- **상단:** 지금 상태를 큰 글씨와 아이콘으로, 한 문장 설명과 함께 표시한다. 오른쪽에는 세 가지를 띄운다.
  - 모드: `LIVE` / `SIMULATION`(가짜 장치) / `PREVIEW`
  - 녹화 여부
  - 사람 제어 가능 / 불가
- **단계 막대 8칸:** 정책 실행 → 실패 징후 확인 → 정지 요청 → 안전 정지 확인 → 리더 동기화 → 인간 교정 → 작업 완료 → 결과 판정. 지금 칸은 ▶ (주황), 다음 칸은 파랑, 끝난 칸은 체크다.
- **가운데:**
  - Wrist 영상 (가장 큼)
  - Front 영상 (보조)
  - 제어 상태 칸 (tap 값 그대로): 정책 명령, 리더 토크, 사람 제어, 녹화 frame, 저장 판 수
  - 오른쪽 상황별 칸:
    - 교정 중: R1 / R2 / R2-O 네모 그림 4칸. 표시 키 m · g 로 지금 칸이 바뀐다.
    - 정책 실행 중: 정지 대상 실패 모습
    - 리더 정렬 중: 손 떼기 경고
    - 결과: 결과 칸
    - 종료 선택: 선택지와 위험
- **아래:** 지금 쓸 수 있는 키 (색 구분: 사용 · 주의 · 무시됨 · 표시 키) 와 안전 · 주의 목록.
- 영상: 미리보기는 합성 영상이고 띠와 영상 안에 `PREVIEW · 합성 영상` 을 표시한다. 가짜 장치는 `SIMULATION · 가짜 장치` 다. 카메라 경로는 바꾸지 않았다 (tap 은 adapter 가 이미 받은 관측을 1/2 로 줄여 씀).

키 설명은 설치된 0.6.2 `_DAGGER_TRANSITIONS` 와 adapter 규칙에서 가져왔다 [코드][가짜 U-d0–d4].

| 화면 상태 | Space | Tab |
|---|---|---|
| 정책 실행 중 | 정지 요청 | **무시됨** (공식 표에 없음) |
| 정지 · 리더 정렬 중 | 무시됨 (A5) | 누르지 말 것 (정렬이 끝나는 즉시 적용되어 리더 토크가 꺼짐) |
| 사람 제어 준비 완료 | 정책 재개 (권장 안 함) | 교정 시작 = 녹화 · 리더 토크 꺼짐 |
| 사람 교정 중 | **무시됨** | 교정 끝 = 저장 · 리더 토크 켜짐 |
| 결과 확인 · 정책 대기 | 정책 시작 / 재개 | 다음 녹화 (원위치면 r) |
| 오류로 잠김 | **무시됨** (A10) | 사람 교정 가능 |

결과 칸 (`hil_qa` 와 같은 규칙):
- 항목: 교정 유형, 복구 완료, 첫 파지, 상자 넣기, 미완성 교정, 원위치, 학습 데이터.
- 표시가 없으면 "검토 필요" 다. 자동 성공 처리는 없다.
- 표시 키는 Tab 저장 **전에** 눌러야 그 판에 들어간다 (QA 귀속 규칙과 같음). 저장 뒤 누른 키는 다음 판에 기록된다는 것을 화면에 적었다.

## 6. 성능 [가짜] (`docs/ui_perf.md`)

| 같은 조작 S7 × 3 | 실효 Hz | 틱 작업 평균 | 예산 (33.3 ms) 넘은 틱 |
|---|---|---|---|
| tap 없음 | 29.88 | 0.77 ms | 0 |
| tap + 화면 (headless) | 29.87 | 0.73 ms | 0 |

- tap 스레드 1 회: 평균 1.1–1.5 ms. p99 는 2–16 ms, 최대 35 ms 까지 나왔다 (가끔). 제어 스레드와 다른 스레드다.
- 480×640 프레임 기준 tap 영상 쓰기: 평균 1.17 ms, p99 1.87 ms (10 Hz → 초당 11.7 ms).
- 화면 그리기 1 장: 평균 26 ms (별도 프로세스).
- 실제 480×640 카메라, π0.5 GPU 추론과 같은 Jetson 에서의 제어 주기는 측정하지 않았다 [미검증].

## 7. 남은 실물 안전 위험 [미검증]

v2 에서 넘어온 위험 (화면은 경고만 하고 줄이지 않음):
- 리더 2 s 자동 정렬 중 끼임
- 토크 off 시 리더 낙하
- 토크 on 시 예전 Goal 로의 이동 (A7 보완)
- hold 뒤 재연결 때 낙하 · 발열
- 소프트웨어 정지 ≠ 안전 정지

화면 때문에 새로 생긴 것:
1. **포커스:** 화면 창이 포커스를 가지면 키가 터미널로 가지 않는다 → Space 를 눌러도 정지되지 않는다. 띠로 경고하지만 정지 지연 위험이 있다. 실제 데스크톱에서 창이 뜰 때 포커스를 가져가는지 확인하지 않았다.
2. **표시 지연:** tap 10 Hz + 그리기 10 Hz 로 화면은 최대 약 0.2 s 늦다. 정지 판단은 로봇을 직접 보고 한다.
3. **안정 시간:** 0.3 s 는 화면 규칙일 뿐이다. 실제 리더가 멈추는 시간은 측정하지 않았다.
4. **창 크기:** 실제 화면 크기에서 창 배치와 축소를 보지 않았다 (`--smoke` 는 창을 숨긴 채 확인).
5. **tap 일시 지연:** 최대 35 ms 지연이 실물 부하에서 제어 주기에 주는 영향은 확인하지 않았다.

## 8. 실제 HIL 수집 전 사용자 확인 항목

1. 화면만 확인 (로봇 연결 없음): `python3 tools/hil_viewer.py --preview`
   - ← / → 로 17 상태를 넘기며 글자 크기, 창 크기, 색을 본다.
   - 수정할 문구나 그림이 있으면 알려 준다.
2. v2 사전 확인 (사용자 실행): 리더 토크 on/off, 정렬 중 손 힘, hold 뒤 재연결 낙하.
3. 첫 파일럿 때:
   - 화면 창이 뜬 뒤 **터미널을 클릭해 포커스를 되돌린다.**
   - Space 가 터미널에서 먹히는지 정책 시작 전에 확인한다 (PAUSED 시작이라 Space = 정책 시작이므로, 첫 확인은 Tab → 원위치 녹화 r → Tab 으로).
   - 화면의 "사람 제어 준비 완료" 와 실제 리더 멈춤 시점이 맞는지 본다.
4. rft01 · eval chain 종료 확인. `run_hil.sh` 가 막는다.
