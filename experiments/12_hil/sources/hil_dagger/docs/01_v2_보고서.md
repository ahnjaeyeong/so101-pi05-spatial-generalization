3. 주 루프의 다음 틱에서 정책 action 을 꺼내기 전에 래치를 확인하고, 아래를 한 번 실행한다:

   - PAUSED 로 강제 전환. 리더는 그 hold 자세로 정렬된다.
4. 이후 PAUSED 의 유지 명령은 오류 순간의 hold 목표다 (공식은 마지막 정책 명령을 계속 보냄).

**이미 보낸 서보 명령은 취소할 수 없다.** [코드][미검증]
- Feetech STS3215 는 위치 서보다. 한 번 쓴 Goal_Position 을 '취소'하는 명령은 없고, 새 Goal 로 덮어쓰는 것만 가능하다. 그래서 A10 은 팔 Goal 을 현재 위치로 덮어쓴다.
- 덮어쓰기 전까지 남는 이동: 마지막 정책 명령은 `max_relative_target=8` 로 present 에서 8° 안이다. 최악은 래치에서 처리까지 1 틱(~33 ms) + 쓰기 왕복 + 서보 가속/감속(Acceleration 254) 동안의 이동이다.
- 가짜 장치에서 1 s 동안 0.29° 움직였다. 실물 값은 측정하지 않았다.
- 그리퍼는 마지막 명령을 유지한다. 큐브를 쥔 상태에서 현재 위치로 바꾸면 쥐는 힘이 빠지기 때문이다.

이 차단이 다루지 않는 것: [코드]
- 추론이 **멈추기만 하고 오류가 나지 않는** 경우 (예외 없이 걸림). 큐가 소진된 뒤에는 새 명령이 나가지 않고 follower 는 마지막 Goal 을 유지한다 (공식 동작). 그 전까지 큐 안의 정상 action 은 실행된다.
- `rollout_guard=warn` 은 이 상황을 로그만 하고 멈추지 않는다.
- 오류가 아닌 잘못된 정책 출력 (예: 지나침). 이것은 사람이 Space 로 멈추는 영역이다.

## 3. 결정 반영 내용

**(1) 교정 녹화 범위 = 정지 → 복구 → 파지 → 상자 넣기**
- 표시 키:

  | 키 | 의미 |
  |---|---|
  | m | 복구 완료 |
  | g / h | 첫 파지 성공 / 실패 |
  | b / f | 최종 작업 (상자 안) 성공 / 실패 |
  | 1 / 2 / 3 | 유형 R1 / R2 / R2-O |
  | r | 원위치 구간 |

- QA 의 `recovery_done`, `first_grasp`, `final_task` 필드로 따로 기록한다. [가짜] QA 매핑 6/6.

**(2) 교정 속도 제한 8° 유지**
- 코드 경로 [코드]:
  - 교정 틱은 `teleop.get_action()` (리더 읽기) → `robot.send_action()` 순서다.
  - `SOFollower.send_action` 안에서 `ensure_safe_goal_position` 이 **보내는 Goal 만** present±8° 로 자른다.
  - 데이터셋에는 자르기 **전** 리더 값 (`processed_teleop`) 이 `action` 으로 저장된다 (`dagger.py` `action_frame = build_dataset_frame(features, processed_teleop, ...)`).
- [가짜] S11 (손 속도 20°/틱):
  - 저장 action − 리더 읽기 = 0.0
  - 저장 action − 실제 보낸 Goal 최대 29.6°, 49 frame 중 28 frame 에서 0.5° 넘게 다름
  - 보낸 Goal − clamp 가 읽은 present 최대 8.0°
  - 손이 느린 시나리오 (S7·S8·S13–S16) 에서는 저장 action = 보낸 Goal (차이 0, 틱당 3.3–4.3°)
- 의미: 사람이 틱당 8° 보다 빨리 움직이면 데이터의 action 은 follower 가 받은 명령보다 앞서고, state 는 뒤처진다. d2 · R1 · RC 는 clamp 없이 녹화돼 action = 보낸 명령이었다.
- QA 의 `frames_action_minus_state_arm_gt8` 로 실물 세션마다 센다.

**팔 필터 OFF 유지**
- `run_hil.sh` 에서 `--arm_filter=true` 를 지웠다.
- `--rollout_guard=warn` 은 filter_log 기록용이다. 이 경우 ArmFilter 가 `enabled=False` 이므로 명령을 바꾸지 않는다.
- [가짜] adapter 9 시나리오 모두 `arm_filter=False`, filter_log `|out−raw|` 최대 0.000, 정책 쓰기 수 = filter_log cmd 행 수. CLI 파싱에서도 `arm_filter False`, `guard warn` 을 assert 했다.

**(3) 종료 · 오류 뒤 자동 복귀 제거**
- `--return_to_initial_position=false` 와 함께, adapter 가 dagger 의 `_teardown_hardware` 를 대체한다.
- 종료 때 터미널에서 직접 고른다:

  | 선택 | 동작 |
  |---|---|
  | home | 시작 자세로 3 s 이동한 뒤 토크 off. follower 통신 오류가 있었으면 선택 목록에 없다 |
  | release | 지금 자세에서 토크 off |
  | hold | 토크 on 으로 종료. Enter · 입력 없음 · Ctrl+C · 터미널 아님 → hold |

- [가짜]:
  - ESC (S8), 추론 오류 (S12), 리더 오류 (S13), follower 오류 (S14), 정상 종료 (S7) 모두 복귀 쓰기 0.
  - home 은 선택한 뒤에만 실행됐다 (S15).
  - hold 일 때 follower · 리더 disconnect 는 토크 off 없이 끝났다.
  - pty 실제 터미널에서 `release` 입력이 반영됐다 (S16).
