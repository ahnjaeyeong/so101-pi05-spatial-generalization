## 0. 결론 (한 줄씩)

1. **설치된 0.6.2 에 공식 HIL (`lerobot-rollout --strategy.type=dagger`) 이 이미 있고, SO-101 leader · π0.5 RTC 조합으로 그대로 돈다.** [코드][가짜]
   상태기계, 정책 정지, RTC 큐 처리, 리더 자동 정렬, 교정 녹화, `intervention` 열 기록을 새로 만들 필요가 없다.
2. 업그레이드는 필요 없다. main 과의 차이 중 HIL 관련 항목(저장 중 정지, 위치 hold, I/O 오류 뒤 복귀 생략)은 교정만 녹화하는 모드에서 adapter 로 덮이거나 영향이 작다. [코드]
3. 공식 코드를 그대로 쓸 때 실물 전에 보완해야 할 곳은 6 곳이다. 모두 lerobot 를 고치지 않는 런타임 adapter 1 파일 (`tools/hil_dagger_entry.py`) 로 처리했고, 가짜 장치에서 확인했다. [가짜]
   - d2 평가 조건(팔 필터)이 dagger 에 안 걸림
   - 정지 직후 Space 를 한 번 더 누르면 정책이 바로 재개됨
   - 교정이 끝날 때 리더가 정지 자세로 튈 수 있음
   - 모델 로딩 직후 정책이 바로 움직임
   - 교정 중 세션이 끝나도 데이터에 표시가 없음
   - 정책 구간 기록이 남지 않음
4. 실물에서 확인해야 할 남은 위험은 8 가지다 (§10). 이 중 Feetech 리더의 토크 재활성화 동작, 리더 무중력 낙하, 종료 시 자동 복귀 동작은 사용자가 직접 실행하는 짧은 확인이 먼저 필요하다. [미검증]

## 1. 외부 HIL 방법 핵심 차이 [문서]

출처: LeRobot HIL 문서 (main, 2026-11-04 확인), RaC arXiv 2509.07953 v1, IWR arXiv 2012.06733, HG-DAgger arXiv 1810.02890, Sirius arXiv 2211.08416.
상세 노트 (영문, 근거 구간 표시): `docs/04_papers_notes_en.md`

| | LeRobot `dagger` | HG-DAgger | RaC | IWR | Sirius |
|---|---|---|---|---|---|
| 개입 시점 | 사람 판단 (Space) | 사람 판단 | 사람 판단, 자동 탐지 없음 | 사람 판단 (폰 버튼) | 사람 판단 |
| 제어권 전환 | 정지 → 리더를 follower 로 이동 (2 s) → Tab 으로 사람 제어 | 사람이 즉시 인수 | VR clutch (상대 동작, 정렬 불필요) | 폰 버튼으로 정지/재개, 상대 pose 명령 | IWR 와 같음 |
| 저장 | 기본: 교정 구간만, 교정 1회 = 1 판. 옵션: 전체 + `intervention` | 사람 구간만 | 개입이 있었던 판은 사람 구간만. 개입 없이 성공한 판은 전체 | 전체 + 개입 표시 | 전체 + 4 분류 (demo/intv/robot/preintv) |
| 개입 뒤 | 정책 재개 (같은 상황 계속) | 정책 재개 | **판 종료** (Rule 2) | 정책 재개 | 정책 재개 |
| 복구/교정 구분 | 프로토콜로만 설명, 표시 없음 | 없음 | Rule 1: 복구 뒤 반드시 교정. 저장은 is_human 1 개뿐, 구분은 사후 분석 | 없음 | 없음 |
| 학습 | 원본 + HIL 병합 → 일반 BC fine-tune | 원본 + 사람 구간 BC | 매 라운드 누적 BC (가중 없음) | 배치마다 개입:비개입 = 50:50 (α=\|D_R\|/\|D_I\|) | intv 50 %, preintv 0 %, demo 자연 비율, robot 나머지 |
| 개입 직전 정책 구간 | 학습 데이터에 없음 | 없음 | 버림 | **버리지 않음** | 15 step (~2 s) 버림 |
| 근거 규모 | — | 자율주행 | 실물 3 과제, 300M MM-DiT 처음부터 학습 (VLA 아님) | 시뮬레이션, 저차원 LSTM | 실물, BC-RNN |

- LeRobot 문서는 이 전략을 HG-DAgger 의 정지→인수→반환 구조에 RaC 의 recovery→correction 프로토콜을 따른 것으로 설명한다.
- "개입 직전 정책 구간을 버린다"는 규칙은 IWR 가 아니라 Sirius 의 것이다. IWR 는 아무것도 버리지 않는다.
- RaC 의 Rule 2 (개입 뒤 판 종료) 는 ablation 에서 계속 진행하는 경우보다 확장성이 좋았다고 보고됐다.

## 2. LeRobot 공식 HIL 의 실제 지원 기능 [문서][코드]

| 기능 | 공식 문서 | 0.6.2 코드 (`rollout/strategies/dagger.py`, `rollout/configs.py`) |
|---|---|---|
| 진입점 | `lerobot-rollout --strategy.type=dagger` | 있음 (entry point `lerobot-rollout`) |
| 상태기계 | Space 정지/재개, Tab 교정 시작/끝, Enter 업로드, ESC 종료 | `AUTONOMOUS ⇄ PAUSED ⇄ CORRECTING`. 유효하지 않은 전환(예: 정책 중 Tab)은 버림 |
| 정지 | 정책 멈춤, 로봇 자세 유지 | `engine.pause()` (RTC 스레드 멈춤, **큐는 비우지 않음**). PAUSED 동안 마지막 명령을 매 틱 다시 보냄 |
| 리더 동기화 | 정지 시 리더가 로봇 자세로 이동 (토크 on) | `teleop_smooth_move_to(teleop, 마지막 명령)` — 2 s · 30 Hz 선형 보간, **이 동안 루프가 막힘** (follower 명령 없음) |
| 사람 제어 | Tab → 리더 토크 off → 녹화 | `teleop.disable_torque()` → 매 틱 리더 읽기 → follower 명령 → frame 기록 (`intervention=True`) |
| 교정 끝 | Tab → 저장 | `teleop.enable_torque()` (Goal 레지스터를 쓰지 않음) → `save_episode()` (교정 1회 = 1 판) |
| 정책 재개 | Space | interpolator reset · `engine.reset()` (큐 비움 + epoch 증가 → 진행 중 추론 결과 버림) · resume · 리더 토크 off |
| 녹화 모드 | 기본 교정만 / `record_autonomous=true` 전체 | 같음. 전체 모드는 streaming encoding 강제, 판은 시간(영상 크기) 기준 자동 분할 |
| `intervention` 열 | 병합 전에 `remove_feature` 로 제거 | `extra_dataset_features` → bool (1,) |
| 추론 | sync / rtc (Pi0, Pi0.5, SmolVLA) | sync / rtc (`remote` 는 main 에만) |
| 입력 장치 | 키보드 / USB 발판 | pynput (X11 전역) → Wayland/헤드리스면 터미널 |
| 안전 정지 | 언급 없음 | 없음. ESC · 오류 → 진행 중 판 저장 → 시작 자세로 3 s 복귀 (`return_to_initial_position=true` 기본) → 토크 off |
| 자동 실패 탐지 · 복구/교정 표시 · 개입 가중 학습 | 없음 | 없음 |

## 8. 수집 및 QA 설계

**방식 결정: A (교정만 녹화, 공식 기본) + 정책 구간 최소 기록.**
- 정책 구간 기록 3 가지:
  - adapter A4 정지 직전 3 s 스냅샷
  - filter_log.csv (정책 구간 매 틱 state · 필터 전/후 명령)
  - debug.log (RTC 지연·clamp)
- 방식 B (`record_autonomous=true`) 는 streaming encoding 이 강제되고 판이 시행 단위가 아니라 영상 크기 기준으로 잘린다. 실패 과정 분석이 필요해질 때 따로 쓴다.

**1 시행 절차 (adapter 기본값):**
1. 로딩이 끝나면 PAUSED 상태다. 리더는 follower 자세로 정렬된다. 큐브를 계획 위치에 놓는다.
2. Space → 정책 실행.
3. 실패 징후가 보이면 Space → 정지 (리더가 2 s 동안 스스로 움직이므로 손을 뗀다).
4. 리더를 잡고 Tab → 교정 녹화 시작 → 유형 키 1/2/3.
5. 복구 → m → 교정 (파지, 이어서 상자 넣기 — 아래 사용자 결정 1) → g 또는 f → Tab (저장).
6. RaC Rule 2 에 따라 정책을 재개하지 않는다: Tab → r → 리더로 원위치 → Tab (이 판은 학습 변환에서 빠지고 원본은 남는다) → 1 번으로 돌아간다.

**개입 행동** (정책이 물리 한계·충돌 위험까지 가도록 기다리지 않는다):

| 유형 | 정지 시점 | 사람 동작 (교정 녹화 안) |
|---|---|---|
| R1 pan 지나침 | 큐브를 지나 반대로 가기 시작할 때 | pan 되돌림 (팔 접은 채, d2 사람 시연처럼) → m → 정렬 → 정상 파지 |
| R2 접근 부족·좌우 정렬 | 닫기 전 (큐브가 손가락 사이 아님) | 그리퍼 열어 둠 → m → 추가 접근·정렬 → 파지 |
| R2-O 빈 파지 | 이미 빈 파지 뒤 | 그리퍼 다시 열기 → m → 재접근·정렬 → 파지 |

- 개입 원인, 시작 상태, 성공 여부는 세 가지로 남긴다:
  - 키 표시와 `hil_events.jsonl` 의 정지 순간 follower 자세
  - 스냅샷
  - QA 표
- 공식 프로토콜은 연속된 한 교정 판 안에서 복구→교정을 이어 하므로, 두 구간을 학습 판으로 나누지 않고 m 표시 frame 만 메타데이터로 남긴다 (RaC 도 저장은 is_human 1 개).

**QA (`hil_qa.py`, 판별):**
- 측정 항목:
  - frame 수 · 시간
  - `intervention` 모두 True, task 문장 = d2, timestamp 간격, 영상 길이 − 데이터 길이
  - 유형 · 복구 끝 frame · 결과
  - 원위치 여부 · 교정 중 종료 여부
  - 첫 frame action−state (전환 점프)
  - 그리퍼 min/max · 시작 pan
  - 직전 스냅샷 파일
- 변환 제외 사유는 지시 §8 그대로 적용하며, 판정은 하지 않는다: 원위치(r) · 교정 중 종료 · 사람 교정 실패(f) · 15 frame 미만.
- 원본 세션 폴더는 지우지 않는다. 학습용은 별도 사본으로 만든다.

**사용자 결정이 필요한 것:**
1. 교정을 어디까지 녹화할지: 파지까지인지, 상자 넣기까지인지. 참고로 d2 판은 상자 넣기까지 들어 있고, R1/RC16 은 평균 383 frame (12.8 s) 이다.
2. A8 교정 구간 clamp: keep 8 (현재 기본) 또는 none (d2 · R1 · RC 녹화와 같음). none 은 실물 Tab 순간 리더−follower 차이를 측정한 뒤에 정한다.
3. ESC · 오류 뒤 시작 자세 자동 복귀 (lerobot 기본 true) 를 유지할지 여부.
