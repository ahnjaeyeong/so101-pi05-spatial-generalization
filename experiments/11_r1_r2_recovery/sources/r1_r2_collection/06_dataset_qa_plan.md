# 06. 데이터 품질 검사 · 수집 현황 관리

## 1. 녹화 중 (자동, 화면)

| 항목 | 어디서 | 기준 |
|---|---|---|
| 시작 자세 | 녹화 프로세스 안 + 터미널 키 차단 | BLOCK 이면 녹화 시작 안 함 (03 §4) |
| 두 카메라 프레임 | 영상 창 '화면 갱신 N s 전' · 카메라 같은 프레임 반복 수 | 1 s 넘게 안 바뀌면 노란 글씨 |
| 제어 주기 | 상태 패널 Hz · 늦은 틱(>50 ms) | 30 Hz 의 95% 미만이면 노란 글씨 |
| 기록 수 | 기록 프레임 = state·action 같은 수 (틱마다 1줄) | 판 끝에 터미널 한 줄 요약 |
| 저장 | 파란 배너 → '저장 완료' (record_ui 와 같은 판정) | — |
| 준비 자세 → 첫 프레임 이동 | rec_start 사건 | > 5° 면 경고 (저장 중 리더 움직임) |
| 큐브 검출 | 손목·front 빨강 검출 | 표시만 (WARN) |

## 2. 실행 뒤 (`r12_collect.py qa --session <세션>`, dataset 읽기만)

보고서 `<세션>/qa/r12_qa_report.md` + 판별 표 `<세션>/qa/r12_qa.csv`. 판정 규칙 (보고서 끝에도 적힘):

| 검사 | 규칙 |
|---|---|
| d2 형식 | info.json `features` 9개·이름 집합·fps·robot_type·codebase_version, tasks.parquet 가 d2 와 같음 |
| 길이 | < 3 s ⚠ · = episode_time_s (시간 초과로 끝남) ⚠ |
| 시간 | timestamp 간격 − 1/fps > 1 ms ⚠ |
| 값 | state/action NaN·inf ⚠ · 한 프레임 사이 팔 관절 변화 > 20° ⚠ (state·action 각각) |
| 시작 자세 | 첫 프레임 state·action 으로 안전 검사 다시 → BLOCK ⚠, WARN 기록 · 시작 그리퍼 값 · 준비 자세→첫 프레임 > 5° ⚠ |
| 파지 | 명령 그리퍼 열림(>15) 뒤 첫 닫힘(<10) 시각 기록, 없으면 ⚠ |
| 끝 자세 | 끝 프레임 lift < −90 · elbow > 85 (쉬는 자세, d2 끝 프레임 p5–p95 기준) 아니면 ⚠ |
| 첫 화면 | dataset 영상 첫 프레임에서 손목 큐브 (시나리오가 '보여야 함' 인데 없으면 ⚠, dx/dy 기록) · front 큐브 ↔ 계획 K > 2.5 cm ⚠ |
| 메타데이터 | r12_episodes.csv 줄 없음 ⚠ · 결과 미입력 ⚠ · 최종 실패 ⚠ · 늦은 틱·카메라 반복 > 0 ⚠ |
| 분포 | 시나리오별 저장/계획, K별, 각도별, 어긋남 방향별 편수, 시나리오별 손목 dx (평균·최소·최대) |

손목 dx 표는 R1-L/R1-R, R2-LEFT/R2-RIGHT 시작 화면이 영상의 어느 쪽에 오는지(부호)를 시나리오별로 보여 준다. 로봇 좌우 ↔ 손목 영상 좌우 관계는 아직 측정된 적이 없으므로, 첫 실행 뒤 이 표로 확인한다.

## 3. 현황 관리

- `r12_collect.py status --session <세션>`: dataset 편수 · 유효 목표 · 저장/제외 · 시나리오별 막대 · 다음 판 · 시도(저장/버림) · 결과 입력 수 · 메타데이터 문제.
- 영상 창 오른쪽 아래: 시나리오별 저장/목표 (계획 상태 + 이번 실행 저장).
- 저장된 판을 버릴 때: `exclude --episodes N --reason ...` → 계획에 같은 시나리오 재촬영 줄 추가, `r12_attempts.jsonl` 에 excluded 사건. dataset 은 그대로.
- 판 결과를 나중에 고칠 때: `label --episode N --result 1|2|3 [--retry K] [--notes ...]` (사건 추가, 마지막 값이 씀).
- `sync`: dataset `total_episodes` 기준으로 `r12_plan.csv` 상태·프레임 수와 `r12_episodes.csv` 를 다시 만든다 (record 뒤 자동).
