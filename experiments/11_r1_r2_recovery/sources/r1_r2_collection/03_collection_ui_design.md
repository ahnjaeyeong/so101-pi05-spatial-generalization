# 03. 수집 UI 설계

## 1. 구조

```
터미널 (사용자가 키를 누르는 곳)
 └─ r12_collect.py record ──────────────── record_ui.py 를 모듈로 불러 그대로 사용
      │  precheck · sidecar · notes · run_lerobot(pty, 저장 중 키 차단) · postprocess
      │  UI 클래스만 R12UI(record_ui.UI 상속) 로 바꿔 끼움: 배너·결과 입력·→ 차단
      │
      ├─ pty 자식: r12_record_entry.py  (LEROBOT_RECORD 자리)
      │     = lerobot 0.6.2 lerobot_record.record() 그대로 + 이름 4개만 바꿔 끼움
      │       record_loop          → 준비 단계 삽입 + 시작 자세 검사 + 녹화 판 집계
      │       init/log/shutdown_visualization → 화면 탭 (/dev/shm 에 프레임·상태 쓰기)
      │     표준 출력에 '[r12] {json}' 사건 줄 → R12UI 가 읽음 (원본 로그에도 남음)
      │
      └─ 영상 창: r12_viewer.py (Tk) — /dev/shm 파일만 읽음, 장치 안 엶, 키 안 받음
            frames.u8 (front·wrist 마지막 프레임) · status.json (관절·검사·Hz) · ui.json (단계·시나리오·결과)
            → vision.json (빨강 큐브 검출) 을 씀
```

새 녹화 엔진은 만들지 않았다. dataset 을 만드는 코드(`LeRobotDataset.create/resume`, `add_frame`, `save_episode`, 영상 인코딩), 리더·팔로워 연결, 관측·명령 처리기는 모두 lerobot 의 것이다. 녹화 명령의 lerobot 옵션은 `r12_collect.py` 가 d2 명령과 같게 만든다 (손으로 옵션을 넣으면 거부).

## 3. 판 단계 (상태)

| 단계 | 녹화 | 시작 | 끝 | 화면 |
|---|---|---|---|---|
| 준비 SETUP | 안 함 | 첫 판 앞, 다시 찍기 앞 (진입점이 끼워 넣음) | → + 검사 통과 / Esc | 노란 배너: 시나리오·큐브 자리·시작 자세 안내 |
| 녹화 REC | 함 | 검사 통과 직후 | → (판 끝) · ← (버리기) · Esc (저장 후 종료) · 시간 초과 | 흰 배너 (빨간 제목): 시연 안내·키 |
| 결과·다음 준비 RESET | 안 함 | 녹화 판 뒤 (lerobot reset 단계) | → + 검사 통과 (→ 방금 판 저장 → 바로 다음 녹화) · Esc | 회색 배너: 결과 키·다음 판 안내 |
| 저장 SAVING | — | → 통과 직후 | 저장 끝 | 파란 배너, 키 차단, '리더 팔 그대로' |

- 준비/결과 단계는 시간 초과로 끝나지 않는다 (`reset_time_s` = 설정 `setup_max_s` 3600 s, 그 안에서 시간이 다 돼도 진입점이 다시 준비를 이어감) → 녹화가 저절로 시작되지 않는다.
- RESET 의 ← = 방금 판 버리기 예약. 준비를 이어서 하고 → 로 시작하면 lerobot 이 그 판을 버리고 같은 번호로 녹화한다 (→ 한 번). 되돌릴 수 없다.
- 첫 판 준비에서 Esc → 아무것도 저장하지 않고 끝남 (빈 판 저장 시도 없음, 시험 확인).
- 마지막 판 뒤에는 lerobot 이 reset 을 하지 않으므로 결과를 녹화 종료 뒤 터미널에서 묻는다.

## 4. 시작 자세 검사 (`r12_common.safety_check`)

| 등급 | 조건 (설정 `safety`) |
|---|---|
| BLOCK | 관절값 없음/NaN (11-02 두 번째 완화부터 이것만) |
| WARN | 한계에서 12° 안 (5° 안 = "쉬는 자세?") · \|pan\| > 95° · d2 접근 구간 범위(p0.5–p99.5) 밖 · 리더−팔로워 > 10° · 그리퍼 < 15 |

- 두 겹: (1) 터미널 UI 가 status.json(1.5 s 이내)에 BLOCK 이 있으면 → 키를 lerobot 에 넘기지 않음, (2) 진입점이 → 로 준비가 끝날 때 마지막 관측으로 다시 검사해 BLOCK 이면 녹화하지 않고 준비를 계속. (2) 는 영상 창·UI 와 무관하게 녹화 프로세스 안에서 판정.
- 탁자·상자 충돌 가능 자세는 관절값만으로 판정할 수 없다 (FK 오차) → 리더−팔로워 차이(막혀서 밀고 있음)를 BLOCK 으로 두고, 나머지는 체크리스트·영상으로 사람이 확인.
- 큐브 검출(손목·front)은 WARN 표시만.

## 5. 키 (터미널에서만)

| 키 | 단계 | 동작 |
|---|---|---|
| → / n | 준비·결과 | 검사 통과 시 녹화 시작 (결과 단계면 방금 판 저장 후) |
| → / n | 녹화 | 판 끝 |
| ← / r | 녹화 | 이번 판 버리기 (결과 단계에서 다시 준비) |
| ← / r | 결과 | 방금 판 버리기 예약 |
| Esc / q | 준비 | 녹화 없이 종료 |
| Esc / q | 녹화·결과 | 방금 판 저장 후 종료 (lerobot 동작과 같음) |
| 1 / 2 / 3 / 0 | 결과 | 첫 파지 성공 / 재시도 후 성공(누를 때마다 재시도 +1) / 실패 / 지우기 |
| m | 결과 | 메모 입력 (Enter 저장, Esc 취소 — 메모 중 키는 lerobot 에 안 감) |
| ? | 아무 때 | 키 안내 |
| Ctrl+C | 아무 때 | 비상 정지 (항상 전달) |

- d2 키(→ ← Esc n r q)는 그대로. 새 키(숫자·m·?)는 lerobot 이 쓰지 않는 키이며, UI 가 먹고 lerobot 에 넘기지 않는다. 키는 어느 것도 서보 명령을 만들지 않는다 (팔은 리더로만 움직임). 저장 중에는 키를 버린다 (record_ui 와 같음).
- 영상 창은 키를 받지 않는다 (g 격자, d 검출 표시 토글만).

## 6-0. 시각 안내 (2026-10-30 사용자 요청: 말 대신 위치를 보여 주기 + 큰 글씨)

- 맨 위 큰 글씨 = 시나리오 이름 (`label`, 예: **R2 · PAN 정렬 불량 (왼쪽)**, R1 보라 / R2 청록 바탕). 그 아래 지금 할 일 한 줄 (① 준비: 주황 ✕ 로 이동 → Pan 지금/목표 · ② 녹화 중: 시연 · ③ 결과 1·2·3 → 다음 판).
- 판마다 세 위치 (계획 `r12_plan.csv` 의 `cube_xy_cm`, `start_xy_cm`):
  - **계획 위치** 초록 ■ = 큐브 K.
  - **시작 위치 (오답)** 주황 ✕ = 로봇 밑동에서 Pan 목표 방향, 거리 = 큐브 거리 + `start_radial_cm` (R2-AHEAD −2.5, R2-LOW −2, 나머지 0). 높이는 그림에 안 보여 글로 (`start_height`).
  - **경유 위치** 파랑 ○ = 큐브 바로 위 정렬 지점 (R1 만, `via`).
  - **지금 Pan** 하늘색 화살표 = 실시간 pan 방향 → 주황 선에 겹치면 시작 위치 방향.
- 그리는 곳: (1) 왼쪽 아래 '위에서 본 탁자' 지도 (위 = 상자, 왼쪽 = 로봇 왼쪽 — 배너 K 격자와 같은 방향), (2) front 영상 위 탁자 면 (front H 보정으로 투영).
- 방향 = `pan_phi`: K 의 기준 pan 에서 정확히 그 K 를 향하고, pan 이 1° 늘면 1° 오른쪽 (밑동 `robot.base_xy_cm`). 손목 위치(FK)는 쓰지 않으므로, 시작 위치의 **거리·높이는 눈대중**이고 Pan 방향만 실시간으로 맞춘다.

## 6. 화면 창 배치

- 위: 유형(R1/R2) · 세션 · episode · 진행률(저장/목표) · 단계 (색) · 녹화 경과. 그 아래 경고 줄 (PREVIEW 표시, 상태 갱신 끊김, 탭 오류).
- 왼쪽 Front: 계획 K 위치(노란 원), 빨강 검출(초록 네모), 탁자 좌표 cm (front H) 와 계획 K 거리.
- 오른쪽 Wrist: 중앙 십자·4분할 격자, 큐브 상자·중심선, dx/dy, 가장자리 경고.
- 아래 왼쪽 (시나리오·시작 조건): 시나리오, 큐브 자리·각도, 어긋남 크기, **Pan 목표와 지금 pan·남은 각도 (±6° 안 초록)**, 시작 자세·시연 안내, 실시간 시작 자세 검사 (✓/⚠/✗). 녹화·저장 중에는 '판정 안 함 (참고)' 로 흐리게.
- 아래 가운데 (녹화 상태·관절): 단계, 기록 프레임 수, 제어 주기 Hz, 늦은 틱(>50 ms), 카메라 같은 프레임 반복 수, 이번 실행 저장 수, 관절 표(팔로워·리더·차이), 단위.
- 아래 오른쪽 (조작 키·저장 결과): 단계별 키, 방금 판 결과·메모, 최근 저장, 시나리오별 저장/목표.

## 7. 녹화 품질 측정 (녹화 프로세스 안)

- 기록 프레임 수 = 녹화 단계에서 `log_visualization_data` 가 불린 횟수 (lerobot 이 `add_frame` 뒤에 부름). 가짜 로봇 시험에서 저장된 판 길이와 같음 (30, 31 프레임).
- 늦은 틱 = 틱 간격 > 1.5/fps. 카메라 반복 = 성긴 표본(97×89 간격)이 직전 프레임과 같음.
- 탭은 2틱마다 프레임 2장 복사(1.8 MB), 3틱마다 상태 json 쓰기. 탭 오류는 한 번 알리고 탭만 끈다 (녹화 계속).

## 8. 한계

- 실물 로봇·카메라로는 아직 실행하지 않았다 (승인 전). 실제 30 Hz 루프에 탭이 더하는 시간은 실물에서 늦은 틱 수로 확인해야 한다.
- → 를 누른 뒤 lerobot 저장(영상 인코딩) 동안 팔로워는 마지막 목표에 멈춰 있고, 저장이 끝나면 그때 리더 자세로 녹화를 시작한다. 그 사이 리더를 움직이면 시작 자세가 바뀐다 → 배너로 안내하고, 준비 자세와 첫 프레임 차이(`start_shift_deg`)를 기록·5° 넘으면 경고. (d2 수집에도 있던 구조.)
- 키는 터미널 창이 포커스일 때만 먹는다 (d2 와 같음). 영상 창을 클릭했으면 터미널을 다시 클릭.
- 큐브 검출은 빨강 HSV 뿐. front 는 로봇에 가려지면 못 찾거나 중심이 치우친다.

## 9. 손목 영상 '닫기 영역' (2026-10-30)

- `tools/r12_wrist_zone.py` 가 d2 256편에서 '닫기 시작' 프레임(명령 그리퍼가 열린 뒤 처음 <10 이 되기 전, 계속 줄어들기 시작한 프레임)의 손목 영상 빨강 큐브 중심을 잼 → `config/r12_wrist_zone.json`.
  - 검출 255/256. 중앙 u 0.361 · v 0.706 (화면 가운데가 아니라 왼쪽 아래). v 와 넓이 상관 0.76 (아래일수록 크게 = 가까이).
  - 주 덩어리(넓이 > 0.08, 86%) 의 u·v p2.5–p97.5 = **u 0.255–0.432, v 0.633–0.780, 넓이 ≥ 0.08**. 이 영역 안에서 닫기 시작한 비율: 주 덩어리 88.6%, 전체 76.5%. 나머지(넓이 ≤ 0.08)는 닫기 시각 중앙 13.1 s (주 덩어리 9.05 s) — 늦은·두 번째 닫기가 많음.
  - 처음 쓴 축별 p10–p90 영역은 사람 시연 t1_known 의 52% 만 안 → 넓힘. 넓힌 뒤 t1_known 50/66 (76%), 밖 16판은 K 마다 0–3 판으로 퍼짐.
  - d2 K1 정책 빈 닫기의 큐브 위치 v 0.54–0.60 (pan_inference_diagnostic 13 문서) 은 영역 아래 경계 0.633 밖.
- 화면: 손목 영상에 점선 상자 '닫기 영역', 큐브 상자 (안 = 초록, 밖 = 주황), 밖이면 큐브 → 영역 화살표, 아래 큰 글씨 '✓ 닫기 OK' / '더 진입 (큐브가 아직 앞·작음)' / '너무 들어감' / '큐브가 영역 왼쪽·오른쪽'. 화면 좌우 ↔ pan 부호는 d2 에서 잴 수 없어(닫기 1 s 전 상관 −0.07) 글로 쓰지 않고 화살표만.
- 표시만 한다 (녹화·닫기를 막지 않음). QA 는 판마다 '닫기 시작 때 손목 큐브가 영역 안인가' 를 기록.

## 10. 큐브 각도 (2026-10-30)

- 계획 각도 (0 · ↺30 · ↻30 · 45, d2 와 같은 규칙: 로봇에 가장 가까운 면과 로봇 좌우선의 예각, ↺ = 위에서 반시계).
- 화면: front 영상 K 자리에 목표 각도로 돌린 큐브 윤곽 (흰 점선), 지도에 돌린 초록 정사각형 (검은 변 = 로봇 쪽 면), 왼쪽 패널 큰 글씨 '각도 지금 ↺24° → 목표 ↺30° ✓'.
- 측정 = d2 와 같은 `~/so101_boxpick/scripts/cube_angle.py` `measure_at` (front 윤곽을 탁자 좌표로 편 뒤 카메라 반대쪽 윗면 모서리 방향). 녹화 프로세스가 보내는 front 프레임으로 준비 단계에서 실시간. 허용 범위 = 이웃 각도와의 가운데까지 (d2 QA 와 같음).
- 검증: t1_known 66판 첫 화면 vs 계획 각도 → 맞음 56, 범위 밖 7 (33–41° 경계), 못 잼 3 (K5, 쉬는 자세 그리퍼가 가림).
- 팔이 큐브 위에 있으면 front 에서 윤곽이 가려져 못 잴 수 있다 → 순서: ① 큐브 각도 ✓ → ② 주황 ✕ 로 팔 이동. 각도가 범위 밖이면 '지금 할 일' 줄이 각도를 먼저 보여 준다. 표시만 (녹화를 막지 않음). QA 는 첫 화면 각도를 다시 재서 범위 밖이면 ⚠ (`angle_first`).
