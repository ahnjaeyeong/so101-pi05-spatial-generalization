## 2. 그림 언어 (`tools/r12_schematic.py`, `screenshots/collector_schematic_sheet.png`)

| 요소 | 그림 |
|---|---|
| 큐브 | 빨간 네모 (실선 = 지금 상대 위치) |
| 그리퍼 손가락 | 회색 막대 2 개 (벌어짐 = 열림 · 가까움 = 닫힘 · grasp = 큐브 양옆에 붙음) |
| 참고 목표 위치 | 초록 점선 네모 |
| 화면 속 위치 변화 | 파란 화살표 (흰 테두리) |
| 하면 안 됨 · 올바른 예 | 빨간 X · 초록 체크 |
| 화면 끝 잘림 | 잘린 쪽 빨간 띠 |
| 작은 그림 | 오른쪽 위 (예: ③ 의 '화면 끝' 잘못된 예) |

- 그림은 손목 화면처럼 그렸다. 손가락은 화면 아래에서 올라온다. 화면 위쪽 = 손가락 끝보다 앞이다.
- 그림마다 '개념도' 표시가 있다. 왼쪽 칸 머리에 '파란 화살표 = 화면 속 위치 변화 (로봇 이동 방향 아님)' 를 적었다.
- 카메라–로봇 좌표 변환은 검증되지 않았다. 그래서 Pan · Lift · Elbow 이동 명령이나 관절 화살표는 그리지 않는다.
- 장면은 설정 (yaml) 의 dict 로 적는다: `grip` · `cube [u, v]` · `ghost` · `target` · `arrow` · `mark` · `cut` · `inset` · `tag`.
- 장면은 크기별로 한 번만 그려 캐시한다. 장면당 그리기 시간은 §9 에 있다.

## 4. 실패 그림 · 지금 화면 관찰 (자동 · 보조, `r12_schematic.observe`)

| 그림 | 이름 | 자동 관찰 조건 (손목 2D, 닫기 영역 u 0.255–0.432 · v 0.633–0.78, 여유 0.03) |
|---|---|---|
| A | 앞쪽에 있음 | 큐브 중심 v < 0.603 |
| B | 옆으로 벗어남 | u < 0.225 또는 u > 0.462 |
| C | 화면 끝에 걸림 | 검출 상자가 화면 경계에 닿음 (먼저 판정). 깊이 · 높이 원인은 판정하지 않음 |
| 목표 | 손가락 사이에 보임 (2D) | 영역 안 — 목표 그림에는 '화면상 비슷함 — 깊이 · 접촉은 직접 확인' 이라고 표시 |
| (없음) | 큐브 위치 확인 필요 | 검출 없음 · 손목 영상 1.5 s 넘게 안 바뀜 · 검출 1 s 넘음 · 영역 경계 ± 0.03 · 영역 아래 (잘리지 않음) |

- 불확실하면 어느 그림도 강조하지 않는다. 손목 상자는 흰색, 안내는 회색 '큐브 위치 확인 필요' 다.
- 사람이 고르는 방법: F9 (자동 → 앞쪽 → 옆 → 화면 끝 → 손가락 사이 → 자동 순으로 돎) 또는 오른쪽 그림 클릭 (같은 그림을 다시 누르면 자동). 사람이 고른 것이 자동보다 우선한다.
- 사람 선택은 새 녹화 (다른 시도) 가 시작될 때 풀린다.
- 계획 시나리오 (AHEAD/DEPTH) 와 화면 관찰은 따로 둔다. 예: AHEAD 판에서 큐브가 아래 경계로 가면 '화면 끝에 걸림' 이 강조된다. 이것을 실패 원인으로 기록하지 않는다.

## 5. 단계 (`r12_viewer_guide.GuideUI`)

- 자동 추정 규칙은 09 §4 와 같다.
- 녹화 중에는 같은 추정이 6 번 (화면 갱신 66 ms → 약 0.4 s) 이어질 때만 단계를 바꾼다.
- '③ 닫힘 직전' 으로 바꾸는 근거가 손목 검출이면, 검출이 확실할 때만 바꾼다. 검출 있음 · 경계에 닿지 않음 · 1 s 안의 값이어야 한다. 아니면 지금 단계를 유지하고 근거에 '(검출 불확실 — 자동 전환 안 함)' 을 붙인다.
- 준비 · 결과 단계로 바뀔 때는 바로 바꾼다 (상태로 확실함).
- 수동 선택: F5/F6 · 그림 클릭. 자동으로 돌아가기: F7. 수동 선택은 자동 추정이 달라도 유지되고, 새 녹화가 시작되면 풀린다.

## 13. R1 · R2-O 로 넓히기 (설계, 아직 안 함)

공통 (이미 있음):
- `visual_guide` 만 넣으면 같은 화면이 켜진다. 단계 · 실패 그림 · 목표 그림 · 아래 띠 글을 설정에서 받는다.
- 관찰 · 닫기 안내 · 판정 · 키 · 모드 · 맞춤은 시나리오와 무관하다.
- 수집자 모드는 `guide_stages` 도 필요하다 (단계 추정이 GuideUI 에 있음).

R2-O (닫힌 그리퍼 → 다시 열기):
1. `guide_stages` 추가: ① 닫힌 채 정지 (ref none) → ② 충분히 열기 (none) → ③ 접근 · 정렬 (k_reach) → ④ 한 번 닫기 (k_grasp) → ⑤ 완료.
2. 그림 장면: ① `grip: closed` + 큐브 앞 + X · ② 손가락 바깥 방향 화살표 (새 요소 `spread` 필요) · ③ R2-P ② 와 같음 · ④ grasp + 체크.
3. 실패 그림 후보: '닫힌 채 큐브 앞' · '덜 열고 접근 (< 25)' · '닫힌 손가락으로 밀기'.
4. `auto_stage` R2-O 규칙: 리더 명령 < 15 → ① · 오르는 중 → ② · ≥ reopen_min 뒤 팔 이동 → ③.
5. 시작부터 닫힌 그리퍼를 닫힘 사건으로 세지 않는지 `close_events` 에서 확인 (열림 ≥ 15 를 먼저 지나야 닫힘으로 셈 — 시험 추가).
6. 닫기 안내: ① ② 에서는 그리퍼가 닫혀 있어도 'CLOSED' 대신 '먼저 충분히 여세요' 를 보이도록 단계별 글.

R1 (Pan 지나침 → 복구):
1. 손목 그림으로는 Pan 을 보일 수 없다. 탁자 위에서 본 그림 종류 (`view: top` — 로봇 밑동 · Pan 선 · 큐브) 가 새로 필요하다.
2. 단계: ① 큐브 방향을 지나침 → ② Pan 복구 → ③ 큐브 재정렬 (손목 그림) → ④ 정상 파지.
3. ② 의 복구 화살표 방향은 front 검출 큐브 자리와 Pan 보정 (c 키) 이 모두 있을 때만 그린다. 없으면 화살표 없이 '방향은 영상으로 확인'.
4. Pan 한계 근처 이동을 지시하지 않는다. 글: 'Pan 한계 근처 금지'. 안전 BLOCK (|pan| > 95 · 한계 10°) 은 그대로.
5. 실패 그림 후보: '반대로 감' · '더 지나침' · '손목에서 안 보임'.
6. 시험: R1 · R2-O 장면 · 단계 규칙 · 관찰을 test_collector 에 추가.

## 14. 알려진 한계

- 자동 관찰은 손목 2D 위치뿐이다. 깊이 · 높이 · 접촉은 측정하지 않는다 (ep0 f150: 2D 로는 영역 안이었지만 첫 닫힘은 빈 파지).
- 닫기 영역 (참고 위치) 은 d2 사람 닫기 시작 분포다. 손가락과의 실제 관계를 보증하지 않는다.
- F9 · F10 · 수동 단계 선택은 화면 상태일 뿐 기록하지 않는다 (사건 없음).
- 실물 30 Hz 루프에서 이 창의 영향은 측정하지 않았다. 측정은 Fake Robot (preview) 뿐이다.
- 화면 찍기는 디스플레이 :1 에서 했다. 찍기 전에 창을 맨 위로 올린다. 이 작업 중 한 장에 다른 창이 겹쳐 찍혀 지웠다.
