## 1. 같은 wrist 영상에서 wrist_roll state 만 바꿨을 때 (G1-F, G1-C)

`g1_roll_factorial.py` — d2 020000, 학습 T1 128편 × 닫힘 2.5 · 1.5 · 1.0 s 전 프레임, 고정 noise 4개 (조건끼리 같은 noise), denoise 5 step.

- 요인: roll Δ ∈ {−30, −15, 0, +15, +30}° (state[4] 에 더함, 학습 q01..q99 = −57.0..55.2° 밖이면 건너뜀) × wrist 영상 {base, wu±, wv±} (큐브를 영상 u/v 로 ±1 cm 상당 옮김, exp2 와 같은 `move_blob`).
- 행동 지표: chunk index h (t1.0 → 30 = 닫힘 시각, t1.5 → 45, t2.5 → 49) 의 FK 집게 끝 (탁자 접선 tan · 반지름 rad), pan, wrist_roll 행동.
  roll 행동 변화가 FK 로 끝점을 옮기는 몫을 빼려고, roll 행동을 base 값으로 고정한 끝점(`tipf`)을 주 지표로 한다.
- 기하 (vision_probe 라벨 규약): 영상 상대 위치 rel (cm) → 탁자 = M(θ)·rel, θ = 0.91·roll − 5.5°.

측정값:
| 이름 | 정의 | roll 을 반영하면 | roll 을 무시하면 |
|---|---|---|---|
| G(Δ) | 영상 이동 반응 Rp(Δ) · M(θ+0.91Δ)⁻¹ | Δ 와 무관 | Δ 에 따라 돌아감 |
| w_rot | Rp(Δ) ≈ Rp(0)·R(ψ) 의 ψ 를 기대 ψ_ideal = ∠M(θ)⁻¹M(θ+0.91Δ) 에 회귀 | 1 | 0 |
| w_state | state 만 바꿨을 때 집게 끝 변화 ~ 정책 자신의 이득 G(0) × 같은 영상이 뜻하는 큐브 이동 dC = (M(θ+0.91Δ) − M(θ))·rel | 1 | 0 |
| roll 복사 | Δ(roll 행동) / Δ(roll state) | — | — |

주의: 큐브 상대 위치가 작을수록 (|rel| ~ 0.7 cm) dC 가 작다 (Δ 30° 에서 ~0.35 cm). 그래서 영상 편집 (±1 cm) 과 roll Δ 를 함께 바꾼 회전 검사(w_rot)를 주 지표로 둔다.

## 2. 같은 큐브 상대 위치를 roll 별로 다르게 표현 (G1-RC / RI)

- RC (roll-일관): wrist 영상의 큐브를 기준점 u*, v* 둘레로 Q = M(θ+0.91Δ)⁻¹M(θ) 만큼 회전 이동 (조각도 같이 회전, `cv2.warpAffine`) + state roll += Δ.
  라벨 규약상 탁자 위 큐브의 집게 기준 위치는 그대로 → 실제 로봇 기준 목표 행동 변화 기대값 0 (집게 끝, pan).
- RI (영상만): 같은 회전 영상, state 그대로 → 큐브가 탁자에서 M(θ)(rel′ − rel) 만큼 움직인 것과 같다.
- 지표: w_RC = 1 − Σ⟨RC, RI⟩ / Σ|RI|² (1 = roll 반영, 0 = 무시). |RC|, |RI| 중앙값, pan 변화, RC 의 roll 행동 복사.
- 한계: 배경(탁자 무늬 · 그림자)은 돌리지 않는다. 집게 손가락은 카메라에 고정이라 실제로도 돌지 않는다. 기준점 = 회전축 투영이라는 가정.

## 3. wrist_roll state 의 입력 경로 검증

### 3a. 코드 · 전처리 (CPU, `c3_state_path.py` → `c3_state_path.json`) — 실행함
경로: state → NormalizerProcessorStep (QUANTILES, q01/q99, **자르기 없음**) → Pi05PrepareStateTokenizerProcessorStep (`np.digitize` 256 구간 → 정수 문자열)
→ 프롬프트 `"Task: …, State: 127 142 166 174 130 2;\nAction: "` → PaliGemma tokenizer → **고정된 Gemma** (train_expert_only) prefix KV → Action Expert 는 층마다 prefix KV 를 주의로 읽는다.
Action Expert 입력(suffix)은 noisy action + timestep(adaRMS) 뿐이고 state 는 suffix 에 들어가지 않는다 (`modeling_pi05.embed_suffix`).
확인 항목: 정규화 범위, 구간 폭, 자릿수별 토큰, 범위 밖 토큰, 주의 마스크, 학습 ↔ 추론 같은 전처리기.

### 3b. Expert 가 roll 토큰을 쓰는가 (GPU, G1-KR/KS + G2 주의 질량 · hidden probe)
- KR: Expert 가 roll 숫자 토큰을 못 보게 (`prefix_pad_masks` False, prefix 안 계산은 그대로) → base 행동 변화, 영상 이득 Rp 변화.
- KS: state 숫자 전체를 가림 → base 행동 변화 (state 의존 크기).
- 주의 질량: 첫 denoise step, 층별로 행동 토큰 → {front, wrist, 과제 문장, state(roll 제외), roll, suffix}.
- Expert 층별 hidden (첫 denoise step = 고정 noise 입력, 행동 토큰 평균 1024 차원) 에서 roll · 큐브 위치 해독 (F1 fold 그대로).

## 4. 위치 특징 ↔ 예측 shoulder_pan · 최종 TCP (G2 + CPU)

`g2_policy_frames.py` — F1 과 같은 프레임 (학습 probe 7,810 · 평가 558), 정책 chunk + Expert 내부.
`a2_g2_analyze.py`:
- S1 같은 프레임 · 같은 라벨 · 같은 시간 범위 (h = min(50, 닫힘까지)) 에서 '이후 집게 끝 이동' ~ 라벨 (tan, rad) 기울기: 정책 vs 사람.
  사람 기울기는 관측 회귀라 라벨 잡음만큼 줄어든다 — 정책도 같은 라벨로 회귀해 같은 조건에서 비교한다.
- S2 Expert 층별 probe 정확도 (img→rot, tab, roll) vs F1 KV probe (0.08–0.12 cm).
- S3 같은 probe 를 G1 편집 hidden 에: 층별 g_img (영상 이동을 hidden 이 따라가는 정도), g_state (state roll 만 바꿈), w_RC.
  → KV (F1, g 0.7) → Expert 층 ℓ → 출력 (G_tt 0.10) 중 어디서 줄어드는지.
- S5 F1 해독값 (Gemma L11 V, SigLIP L26) → 정책 pan · 집게 끝 이동 기울기, 사람과 같은 회귀.
- S6 평가 프레임: train 범위 안/밖별 정책 이후 이동 ~ 라벨.

## 6. Expert-only 표본 강화 ablation (설계만, 실행 안 함)

현재 lerobot 0.6.2 `EpisodeAwareSampler` 는 표본 가중치가 없다 (`drop_n_first/last_frames` 만). 학습 코드를 바꾸지 않으려면 **파생 데이터셋**으로 가중한다:
- 판 단위 가중: `lerobot-edit-dataset merge` 로 같은 release 를 여러 번 합침 (예: Random 판 2 회).
- 구간 가중: 접근 구간 [움직이기 시작, 닫힘 + 0.5 s] 만 남긴 사본을 새 스크립트로 만들어 원본과 merge (원본 데이터는 그대로).

| 이름 | 데이터 | 닫힘 3 s 전~닫힘 비율 | 비고 |
|---|---|---|---|
| A0 대조 | d4 그대로, d4 20k 에서 이어 4k step | 18.7 % (d2 기준 M8) | 추가 step 효과 통제 |
| A1 구간 | 원본 + 접근 구간 사본 2 회 | 약 35–40 % | 닫힘 뒤 운반 구간 비중 감소 |
| A2 위치 | Random 판 2 회 + roll×tan 희소 칸 판 2 회 | 그대로 | 위치 · roll 조합 다양성 |
| A3 | A1 + A2 | | |

- 방식: d4 020000 에서 이어 학습 4k step (bs32, lr 2.5e-5 → 일정, ≈ 11 h/run) — 20k 새로 학습(55 h) 대신. 모두 같은 seed · step.
- 오프라인 평가 (로봇 전): G1 지표 (G_tt · G_rr per phase, w_rot, w_RC), S1 정책/사람 기울기 비율, hold-out fold 행동 MAE, 격자 K 당김 (diag exp1).
- 사전 판정: A1/A2 가 A0 대비 (i) 닫힘 1–2 s 전 G_tt 를 bootstrap CI 가 겹치지 않게 올리고 (ii) 사람 대비 기울기 비율이 0.8 이상이면 로봇 평가 후보.
- 로봇 평가는 사용자가 직접 실행 (T1 8 위치 × 2, 같은 순서).

## 7. Expert-only vs VLM fine-tuning 판정 규칙 (결과 전에 고정)

| 관측 | 가리키는 곳 | 다음 학습 |
|---|---|---|
| Gemma KV 에 roll 반영 위치가 선형으로 있음 (F1 no-roll tab R² ≥ 0.8) **그리고** Expert hidden 이 위치를 해독 가능 (S2 ≤ 0.15 cm) **그리고** 출력 이득만 낮음 | Expert 출력 매핑 / 학습 신호 | Expert-only 유지 + 표본 · 데이터 (6절) |
| KV 는 정확한데 Expert hidden 해독이 크게 나쁨 (S2 ≥ 0.30 cm) 또는 KR 가리기 효과 ≈ 0 이면서 w_rot ≈ 0 | Expert 가 prefix 를 읽는 부분 | Expert-only 지만 용량/주의 관련 변경 (expert lr · step), 그다음 LoRA |
| Gemma KV 의 roll · 위치 결합이 부족 (no-roll tab R² < 0.6) 이고 w_rot ≈ 0 | 고정된 VLM 의 state 결합 | VLM LoRA (lerobot PEFT, Gemma q/v) |
| 정책 기울기 ≈ 사람 기울기 (S1, 같은 라벨) | 시연 자체의 보정 크기 | 학습 방식보다 데이터 (보정 · 복구 시연, 위치 다양성) |

비용 메모: full VLM fine-tune 은 Gemma 2B + SigLIP 까지 optimizer 상태가 생겨 Thor 통합 메모리 (122 GB, d4 사용 중 23 GB) 에서 expert-only 보다 수 배 무겁다. lerobot 0.6.2 에 PEFT (`--peft`, LoRA) 가 있어 학습 코드 변경 없이 Gemma 층에 어댑터를 둘 수 있다 (기본 대상은 expert q/v 라 대상 정규식 지정 필요).
