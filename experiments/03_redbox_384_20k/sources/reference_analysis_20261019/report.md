## 3. 가설

### H1 — Redbox 시연이 레퍼런스보다 거칠다 → **기각**
- **근거**:
  - 작은 반전(떨림 지표)은 레퍼런스가 2배 많습니다(0.44 대 0.21/s). wrist_roll은 0.89 대 0.11/s입니다.
  - ≥3 Hz 비율도 레퍼런스가 큽니다(0.052 대 0.032).
  - 두 데이터 모두 10°/프레임을 넘는 점프가 0건입니다.
- **차이점**: Redbox는 **더 빠르고 단호합니다**(속도 +29%, 큰 반전 +28%, 에피소드 −27%). elbow·wrist_flex·gripper는 저주파 파워가 큽니다. ≥3 Hz 비율이 Redbox에서 높은 건 shoulder_pan뿐입니다(0.035 대 0.014).
- **모델과 비교**: 사람 시연 chunk의 부호 바뀜 비율은 0–3%이고, 모델 출력은 44–58%입니다. 모델 잡음은 두 데이터 어디에도 없는 성분입니다.
- **미검증**: action은 리더 팔 값입니다. 녹화 장비(리더 팔 상태, 손 떨림 필터 여부)는 비교하지 않았습니다.

### H2 — T1/T2/T3 혼합으로 action 분포 차이가 커진다 → **근거 없음**
- **근거**:
  - Redbox의 작업별 분포와 전체 분포의 차이(Wasserstein-1 ÷ 전체 q01–q99 폭)는 0.01–0.11입니다. 레퍼런스(0.03–0.11)보다 작거나 비슷합니다.
  - 작업별 범위 ÷ 전체 범위는 0.83–1.06으로, 한 작업이 범위를 넓히지 않습니다.
- **차이점**: Redbox는 task 문장이 2개이고 레퍼런스는 1개입니다.
- **미검증**:
  - 관측 조건에서 행동이 여러 갈래로 갈리는 정도(T2 순서 선택, random 배치)는 action의 주변 분포로는 알 수 없습니다.
  - 혼합이 모델 잡음에 주는 영향은 재학습해야 알 수 있습니다(T1만 학습하는 실험).

### H3 — 일부 불규칙 에피소드가 모델 품질을 떨어뜨린다 → **해당 에피소드 없음**
- **근거**:
  - Redbox에서 고주파 비율이 이상치인 19편 중 14편이 T1입니다. 모두 shoulder_pan이 거의 움직이지 않는(±7°) 에피소드입니다.
  - 전체 파워가 작아서 비율이 부풀었을 뿐이고, 시계열은 매끄럽습니다(`fig3b`).
  - 레퍼런스 이상치 8편(대부분 T3 wrist_roll)도 미세 조정 동작입니다.
- **미검증**:
  - 실패·재시도 같은 "의미상 불규칙"한 에피소드는 영상 검토가 필요합니다.
  - 특정 에피소드를 빼고 재학습하는 실험은 하지 않았습니다.

### H4 — 정규화 범위 차이가 출력 잡음에 영향을 준다 → **일부만 설명함**
- **근거**:
  - Redbox 체크포인트의 정규화 폭은 실제 q01–q99의 1.1–1.4배입니다. lerobot 0.6.2가 합칠 때 분위수를 min/max로 감싸기 때문입니다.
  - wrist_roll은 실제 사용 범위 자체가 146°로, 레퍼런스(50°)의 3배입니다.
  - 그 결과 같은 정규화 잡음이 도 단위로 1.1–1.5배 커집니다.
  - 하지만 **정규화 단위로 바꿔도 Redbox 20k의 잡음은 cubemark 모델의 2.6–5.3배**입니다(`fig6`).
- **미검증**: 실제 분위수로 정규화해서 재학습하면 잡음이 얼마나 줄어드는지는 재학습해야 알 수 있습니다.

## 5. 결론

1. **레퍼런스 action이 더 부드러운가?** 아닙니다. 고주파·작은 반전 기준으로는 Redbox가 더 깨끗합니다. Redbox는 더 빠를 뿐입니다.
2. **데이터 차이로 모델 진동이 설명되나?** 시연의 거칠기로는 설명되지 않습니다. 정규화 범위로는 1.1–1.5배만 설명됩니다. 나머지 약 3배는 학습 결과(학습 설정 또는 데이터 다양성)에서 나옵니다.
3. **고주파가 많은 작업·에피소드는?** T1의 shoulder_pan입니다. 다만 움직임이 작아서 생긴 지표상 효과이고 실제 떨림은 아닙니다. T3이 가장 빠르고 가속도도 큽니다.
4. **데이터 구성과 배치 크기 중 무엇을 먼저?** 학습 설정을 맞춘 대조군을 먼저 하는 게 낫습니다. 같은 expert 학습(bs8, 3k)으로 cubemark는 매끄러웠으니, 같은 설정을 redbox_all에 돌리면 "데이터인가, bs32·20k 설정인가"가 한 번에 갈립니다(약 2.3시간).
5. **공정한 비교 조건**: 다음을 맞추면 됩니다.
   - 학습 설정(정책, 시작 가중치, expert만 학습, 비전 동결, bs, lr, 스케줄러, 스텝, seed, dtype)
   - 통계 계산 규칙(둘 다 같은 방식으로 recompute)
   - 짧은 에피소드 처리
   - task 문장 수(레퍼런스 1개 대 Redbox 2개)
   - 비교 지표(같은 오프라인 chunk 잡음 스크립트를 각자 데이터의 관측에 적용)

   epoch와 스텝 중 하나를 맞추면 나머지는 달라집니다. 이 점은 결과에 명시해야 합니다.
