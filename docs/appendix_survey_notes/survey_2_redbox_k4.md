| 체크포인트 | 학습 loss (1k 구간 평균) | 오프라인 파지 자세 오차 (학습 데이터) | 오프라인 잡음 | 실물 |

| 10k | 0.0260 | 6.17° | 1.09° | 시험 안 함 |
| 15k | 0.0240 | 5.58° | 1.02° | 시험 안 함 |

- 5k → 20k: loss와 오프라인 파지 오차는 꾸준히 줄었지만 잡음은 줄지 않았다. 20k 이전 체크포인트는 실물 시험이 없어, loss 감소가 실물 성공으로 이어졌는지는 이 단계 자료로 알 수 없다.
- 20k → 30k: loss는 거의 같고 (LR 2.5e-6 고정), 실물 첫 파지는 내려갔다.
- 진동은 체크포인트보다 추론 방식(sync 대 RTC)의 영향이 컸다 (E2 대 E8).

## 4. 출처 간 충돌·불일치

1. **A/B 세션 1 대 세션 2**: K 위 판만 첫 파지 세션 1 (16:54, 1–8판) 2/8 대 세션 2 (17:13) 16/20, p=0.011. 지연·시작 자세·진동·추종 오차 차이 없음, 원인 미확인 (analysis_20261019.md).
2. **A/B 계획 위치 대 실제 위치**: 1판(계획 K1)·4판(계획 K2)은 실제로 K3·K4에 놓여 실행됨 (영상 확인). `results/report.md`의 조건×위치 표는 계획 라벨 기준, `analysis_20261019.md`·`space_report.md`의 구역 표는 실제 위치 기준이라 숫자가 다르다.
3. **사람 판정 칸과 메모의 불일치** (plan.csv):
   - A/B 28판: first_grasp = success, attempts 5, 메모 "첫 파지 실패, 미끄러짐".
   - A/B 37판: first_grasp = success, attempts 2, 메모 "첫 파지 실패함. 얕은 파지".
   - A/B 35판: first_grasp = success인데 attempts 3.
   - 공간 20k 39판: first_grasp = failure, 메모 "처음부터 파지 성공했음, 전체파지도 1회임".
   - 공간 30k 17판: first_grasp = success, attempts 5, 메모 "첫파지 실패함".
   - 보고서들은 판정 칸 값을 그대로 썼다. 메모 기준으로 고치면 첫 파지 수가 1–2개씩 달라진다.
4. **T2 첫 실패 원인 정정**: grasp_analysis 초판은 "손목 방향 약 40° 어긋남", 14:15 정정에서 "얕은 파지 깊이 (큐브는 1–7° 정렬)" (같은 파일 상단).
5. **큐브 각도 효과**: 20k 공간 40판만은 첫 파지 67 → 54 → 47%로 각도가 클수록 낮다. 80판 합치면 50 → 57 → 62%로 반대. 문서 결론은 "큐브 각도 자체는 관계 없음".
6. **front 가림 효과**: 20k(80판)는 가릴수록 성공이 높음, 30k는 10–30% 구간이 가장 낮음 (2/14). 일관된 방향 없음.
7. **손목 회전 효과 (20k 대 30k)**: 20k에서는 <30°가 최종 15/15, 30k에서는 7/12. 30k에서는 30–60°가 최종 18/20으로 가장 높음.
8. **빨간 큐브·방해 큐브 수**: T2-R 계획 184 대 census 측정 182; T3-R 방해 계획 258 대 측정 253 (검출 기준 차이로 보임, 원인 미확인).
9. **T2-K 날짜**: README는 2026-10-15, notes.md 녹화 기록은 10-14 16:16 시작 ~ 10-15.
10. **스케줄러 값**: 020000 train_config.json에는 warmup 1000 / decay 30000이 저장돼 있으나 training_params.md는 실행 시 666 / 20000으로 자동 축소됐다고 적음. lr 로그 (step 1000에서 2.5e-5 최고, 20000에서 2.5e-6)는 축소된 값과 맞는다.
11. **메모리 기록과 파일**: 메모리의 redbox-dataset 노트는 "T2-K: C(4,3)=4 combos × 16"이라고 적혀 있으나 실제 데이터는 2–4개 혼합 11가지 배치 (계획 변경 전 기록).
